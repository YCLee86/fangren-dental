## 二、拿到數字之後，兩件事的看法變了

### 2-1　⚠⚠ 「電話忙線」不是偶發，是**結構性**的

六個月 1,886 通 ≈ **每月 314 通** ≈ 每個看診日 **15 通**，而且**這還只是
「從 Google 商家檔案按撥號」那一種**（沒有算直接輸入號碼、名片、招牌、
回診卡上抄的）。

→ 第一輪那位病人說「我有打電話，忙線中」**不是運氣不好**。
→ 所以 LINE 那三則裡「打電話最快」這個指引**是對的，但不夠**：
   我們寫的「忙線就隔幾分鐘再撥」是把問題丟回給他。
   **這一條要帶回去問使用者**：診所要不要考慮第二線、語音信箱、或讓
   LINE 的「不克前往，預約改期」按鈕真的接得住（見 3-2）。

### 2-2　Google 商家檔案**不是「還沒開始做」，它一直是最大的入口**

CLAUDE.md 第九之〇節寫著它「投報率最高、只有使用者能做」，從 8/17 擱到現在。
現在有數字了：**六個月 14,973 個人看過那張檔案、1,886 通電話從那裡打出來。**
相較之下官網是「找資料的人」才會去，商家檔案是「現在就想打電話的人」。

**它值得一個固定的維護節奏**（照片、看診時間、評論回覆），這是第 11 號角色
接下來要提的第一件事。⚠ 但**不要動到看診時間的三組不一致**（CLAUDE.md 第十節）——
那要使用者先定案哪一組才是對的。

### 3-2　⚠⚠⚠ 最要緊的一件：**病人其實可以在 LINE 上改期**

那張卡最底下就是「**不克前往，預約改期**」。
**這推翻了我們前十輪的前提** —— 我們一路寫「改約或取消，打電話最快」，
是因為以為 LINE 上做不到。

**在問清楚之前，三則文案先不要改**（那個按鈕點下去實際會怎樣？
開一個改期頁面？還是只是通知診所、仍然要等人回電？）。
問到之後：

- 如果**真的可以自己改期** → 三則的主要動作要從「打電話」改成
  「**用提醒卡上的按鈕**」，電話退成備援。這會讓那 1,886 通電話少掉一部分。
- 如果**只是通知診所**、還是要等回電 → 文案維持現在的寫法，
  但要在綁定完成那一則講清楚「按了會怎樣」，不然他按了就以為改好了。

### 3-3　這張卡本身的問題（等上面那題有答案再一起處理）

| | 問題 | 為什麼要緊 |
| --- | --- | --- |
| **語序** | 「〔病人姓名〕 **提醒您**，您的看診時間將至」—— 姓名放在「提醒您」前面，讀起來像**那個人在提醒你** | 這是全帳號曝光最高的一句話。⚠ 但**名字本身是必要的**，見 3-4 |
| **名稱不一致** | 標題寫「**斗六**芳仁牙醫診所」，站上與其他所有地方都是「芳仁牙醫診所」 | 同一間診所兩個名字 |
| **語氣** | ⚠ emoji、👉、紅字、驚嘆號 —— 和站上「不推銷、講究」的調子落差很大 | 病人一年看到很多次，這才是他心中芳仁的樣子 |
| **就診須知第 2 條** | 「有發燒/咳嗽/呼吸道症狀等，請來電改約」—— 和底下那顆「不克前往，預約改期」按鈕**互相矛盾**（一個叫他打電話、一個叫他按按鈕） | 兩條路同時給，他會愣住 |
| **⚠ 能不能改** | **未知** —— 這張卡是廠商系統產的，文字改不改得動要問廠商 | 決定這一條是待辦還是已知限制 |

### 6-3　實測證實：**選單按下去會留下一則「像病人自己傳的」訊息**

截圖逐幀可見：病人按了選單 → 聊天室出現一則**綠色（病人側）**的

**這正是第十二節說的那個代價，現在有實證了。** 兩件跟著確定：

1. **關鍵字回應確實會蓋過一般自動回應** —— 那則 `[約診紀錄查詢]` 沒有跳出
   通用的自動回應，只回了查詢結果。**所以「格子連到自己的資訊圖卡」那條路可行。**
2. 廠商用的關鍵字**帶方括號**（`[約診紀錄查詢]`）—— 那是刻意讓它看起來像系統指令、

### 6-4　病人端看得到「此官方帳號正在自動回覆訊息」

截圖的標題列下方就寫著這一行（LINE 自動加的，管理者關不掉）。

**不是新資訊**，它的價值只在「接下來告訴他怎麼找到人」。
⚠ 這不代表要拿掉那句 —— 但可以更短，重點放在後半（打電話 / 按按鈕）。

### 6-5　推播的實況：**診所本來就沒有在做定期推播**

使用者：「診所沒有特別推播什麼。只有重大事件例如**調漲掛號費**和**颱風天休診**，

⚠⚠ **所以第四節那條「第一次推播就當一次實驗」的建議整條收回。**

- **封鎖率 2.2% 的謎解開了** —— 它低，正是因為**幾乎不發**。

→ **這個角色接下來該做的，不是「提議推播」，而是把他們真的會用到的那兩種
群發訊息寫好備著**：**颱風／臨時休診**、**費用或制度異動**。
那兩種都是「事情發生時很急、很容易寫得慌張」的訊息，事先寫好模板才有用。

## 七、⚠ 2026-09-02（更晚）：那個名字是**病人**，而且它是必要的

使用者確認：「提醒上的名字是病人。」

### 7-1　所以我前面的判讀要修正一半

我原本只說「語序讓姓名讀起來像在提醒你」，暗示那個名字可有可無。**錯了。**

截圖的聊天室名稱是「**〔家長姓名〕(哲&丞)**」，而提醒卡上的名字是那兩個小孩其中一個
—— 也就是說：**一個 LINE 帳號在收好幾個家人的約診提醒**。
那個名字是在回答「**這一次是誰要看牙**」，對帶小孩的家長是**非有不可的資訊**。

⚠ **通則：看到一個欄位覺得多餘之前，先問它在替誰回答什麼問題。**
這一次差一點就把唯一能分辨「是哪個小孩」的線索當成贅字。

### 7-2　所以要修的不是名字，是**那一句的語序**

| | |
| --- | --- |
| 現在 | `〔病人姓名〕 提醒您，您的看診時間將至　請問您是否前往看診呢？` |
| 問題 | 名字直接接「提醒您」，讀起來像**那個人在提醒你**；帶兩個小孩的家長還要多讀一次才知道是誰 |
| 建議 | `提醒您：〔病人姓名〕的看診時間快到了` —— 名字留著，位置換到它該在的地方（受詞） |

⚠ 這張卡是廠商系統產的，**改不改得動要問廠商**（同 3-3 的其他四項）。

### 7-3　跟著要問的一題：**家人可以綁在同一個帳號嗎？**

既然一個帳號收得到多個家人的提醒，那綁定那一關是怎麼運作的？

- 如果**一個帳號可以綁多位家人** → 綁定完成那一則應該多一句
  「**家人的約診也可以綁在這個帳號**」，那比「把連結轉給他」更省事，
  也更貼近實際在發生的事（家長替全家管）。
- 如果**一個帳號只能綁一支手機／一個人** → 那第十六節那句
  「把這個連結轉給他就好」就是對的做法，維持原樣。

**這一題沒答案之前，兩則文案都不動。**

使用者回答：

1. **綁定成功那句話可改。**
2. **一個帳號可以綁定多位家人。**
3. **提醒卡的文字可改。**
4. ⚠⚠ **「不克前往，預約改期」按下去，只是系統上顯示取消。** 原話：
   > 「診所會看狀況打給病患確認。如果是重要療程，會儘量在原訂約診時間前和病患
   > 了解確認、改約（**有時候也有誤按**）。如果是定期檢查、回診，就沒有硬性一定要在
   > 原訂約診時間前和病患確認（因為有時候病患就不接電話了，我們當作他不想再來）。
   > **基本上，在這裡按取消已經違反診所和病患的預約協議**（至少兩天前不含假日要更改、
   > 取消，否則日後不受理預約）。」

### 8-1　⚠⚠⚠ 結構性矛盾：**系統在期限那一刻，才遞給他一顆違規的按鈕**

| | |
| --- | --- |
| 診所的協議 | 更改／取消要在看診日的**兩天前（不含假日）** |
| 提醒的時機 | **看診前 48 小時** ＝ 剛好兩天 |
| 中間若跨假日 | 「不含假日」會把期限再往前推 → **提醒送到時已經過期** |
| ⚠⚠ **2026-09-04 補**：沒回應的後果 | **24 小時內沒回應，系統會自動取消約診**並遞補他人（使用者 09-04 提供，見第 19-12 節） |

⚠⚠ **那一條讓這個矛盾嚴重一級。** 原本只是「按鈕遞得太晚」，現在是**不回應就真的失去約診**，
而那 24 小時**可能整段落在休診日**（週一的約診 → 提醒週六發 → 期限在週日，電話沒有人接）。
**這一題要問廠商**：計時會不會跳過休診日、被取消時會不會再通知病人（第 19-12 節）。

**所以那張卡送到病人手上的那一刻，期限剛好到期或已經過期**，
而卡片底下就放著「不克前往，預約改期」。
**等於系統在邀請病人做一件違反協議的事**，事後再由診所打電話去收拾
（重要療程要追、定期檢查就算了）。這解釋了為什麼那顆按鈕還是得靠人工回電。

### 8-2　所以文案怎麼寫（已定稿）

- **三則都不把那顆按鈕寫成改約的管道。** 改約一律指向電話與「兩天前」的規則。
- **也不寫「不要按那顆按鈕」** —— 否定句只會讓它更醒目（COPY.md 第九之十七節 B），
  而且它在某些情況（誤按、真的臨時有事）仍然是有用的訊號。
- **把規則放在他還來得及的時候講** ＝ **綁定完成那一則**（那是他綁完、還沒排下一次約診的時候）。

### 8-3　真正的解不在文案，在**時機**（建議，要問廠商）

既然提醒卡的文字可改、發送時機多半也可設，**最根本的做法是把提醒拆成兩次**：

| | 什麼時候 | 這一則的工作 |
| --- | --- | --- |
| 第一次 | **看診前 3～4 天**（在期限之前） | 「要改期還來得及」—— 那顆按鈕**這時候才有意義** |
| 第二次 | **看診前一天或當天早上** | 「別忘了」—— 這一則**不要放改期按鈕**，只留「我會到」 |

現在的單一次 48 小時提醒，同時想做這兩件事，所以兩件都做不好。
⚠ **要問廠商：發送時機可不可以設定、可不可以發兩次。**

### 8-4　提醒卡的建議改法（文字可改，但臨床那兩行要醫師點頭）

```
芳仁牙醫診所                    ← 拿掉「斗六」，和站上一致

提醒您：〔病人姓名〕的看診時間快到了
2026/07/14（二）19:15

看診前請帶健保卡，並戴上口罩。
如果有發燒或咳嗽，請先打電話給診所。

［我會到］
［不克前往］
```

改了五件：
1. **標題**「斗六芳仁牙醫診所」→「芳仁牙醫診所」（站上與其他地方都是這個）。
2. **語序**：名字從「提醒您」前面移到受詞的位置 —— **名字留著**（一個帳號收好幾個
   家人的提醒，那是唯一能分辨是誰的線索，見第七節）。
3. **拿掉 ⚠🚬👉📅 與紅字**：這是一年會看到很多次的訊息，它就是病人心中芳仁的樣子。
4. **就診須知兩條併成兩句白話**，不用編號、不用『』。
   ⚠ 這兩行是**臨床內容**，要醫師點頭才能改。
5. ⚠ **「請來電改約」與「預約改期」的矛盾解掉**：發燒那句改成「先打電話給診所」，
   和底下的按鈕不再打架。

⚠ 按鈕的文字與行為要不要改（例如按了之後系統回一句「我們收到了，會再打電話
跟你確認」），**等 8-3 的時機問題有答案再一起處理** —— 時機不改，按鈕怎麼寫都尷尬。

只講「你可以怎麼被服務」：蒞臨專門店、或致電客服中心。

**這是一個真正的分歧，不是文字差異。** 我的判斷是**芳仁不能照抄**，理由：

| | HERMES | 芳仁 |
| --- | --- | --- |
| 客人會不會在這裡留言等回覆 | 幾乎不會（他有專門店、有客服中心，也知道精品不走 LINE 客服） | **會** —— 這一整輪的起點就是那位病人留言等回覆、又打了電話忙線 |
| 不說的代價 | 幾乎沒有 | **他會一直等** |

→ **「不說」只有在對方本來就不期待回覆時才成立。**
這也回頭確認了第十五節那個結論：說，但說在第二句、而且下一行立刻給出口。

### 12-2　可以學的兩件

1. **資訊那一則乾淨得像一張名片** —— 名稱、電話、時間、例外，**四行、沒有一句廢話**。
   我們現在的兩層清單已經是同樣的效果，而且只佔一個泡泡，**所以不必學它分成兩則**
   （分兩則會再多一個泡泡，第十三節那個「兩則加起來」的帳要重算）。
2. ⚠⚠ **「國定假日除外」** —— 它用一句話把例外講掉。

### 12-3　⚠⚠⚠ 那句「國定假日除外」讓我們發現一個**沒問到的診所事實**

想照抄的時候去查站上怎麼寫，結果是：

> `index.html` 的門診表底下：**「國定假日與各科特別門診請來電確認。」**

**站上寫的是「請來電確認」，不是「休診」。** 所以：

- ❌ **不能寫「國定假日休診」** —— 那是我們自己推的（全隊紅線第 11 條：診所的事實
  沒問到就不要寫）。
- ❌ 也不能寫「國定假日請來電確認」—— 那一段本來就在講「打電話給診所」，
  變成「打電話問電話有沒有人接」，繞回自己。
- ✅ **這一輪的做法**：把那一行補成「**週一至週五**開診時間內都有人接」，
  週末與國定假日交給站上的門診表（那一項本來就連過去）。

→ **加進待問清單：國定假日到底休不休診？** 問到之後這一句才寫得完整。

### 12-4　沒有學的

「誠摯」「蒞臨」「探索愛馬仕世界」「將會為您提供服務」—— 這是精品的距離感，
和 COPY.md 第十節那條（貼近在地、不端著）正面衝突。**語氣一個字都不抄。**

**它們沒有在講「綁定」這個動作，是在講「綁了之後會收到什麼」，而且一條一條列。**

→ ⚠⚠ **芳仁現在只寫了一條**（「看診前 48 小時它會提醒你」）。
但診所實際上**至少發三種**：

| | 現在有沒有在發 | ⚠ 是不是綁定才收得到 |
| --- | --- | --- |
| 看診前 48 小時的**約診提醒** | ✅ 有（那張提醒卡） | ✅ 是 |
| **治療後的照顧提醒** | ❌ **沒有**。我一度以為有，那是選單「衛教資訊」底下的廠商公版（14-5） | — |
| **臨時休診／費用異動的通知** | ✅ 有（使用者說：颱風天休診、調漲掛號費，對受影響的約診病人群發） | ❓ **應該是**（要知道他有約診），但沒問到 |

**→ 待問使用者：後兩種是不是綁定之後才收得到？** 是的話，招呼訊息可以從一條變三條，
說服力完全不同。

### 13-2　提案頁多了一個開場變體：**利益開場**

```
完成綁定，這三件會發到你手上：
　看診前 48 小時的約診提醒

診療項目、醫師介紹、衛教資訊。
```

**兩種開場的差別，是一個真正的選擇題：**

| | 定案版（定位開場） | 變體（利益開場） |
| --- | --- | --- |
| 第一句 | 這裡是芳仁牙醫診所的官方 LINE | 完成綁定，這三件會發到你手上 |
| 先回答 | **這是什麼**（誠實、不裝人） | **對我有什麼用** |
| 誰在用 | HERMES、早安美芝城、星宇 | **國泰世華、玉山、JINS** |
| 風險 | 他可能沒讀到「要綁定」就滑掉 | 像在推銷（雖然講的是事實） |

⚠ **定案版那個方向是使用者第九輪自己定的**（「不要裝得好像有人」「先講這個帳號是什麼」），
所以我沒有擅自換掉，**兩個都放在提案頁上讓他挑**。
兩版都是 34%，長度一樣。

⚠⚠ **利益開場的後兩條還沒確認**（見 13-1），**沒確認之前不要真的上**。

### 13-3　另外兩件記著、這一輪不做

1. **選單底部那條橫幅**：玉山的選單最下面有一條常駐的
   「❗點我綁定 LINE 通知　重要帳務資訊不漏接❗」。
   芳仁的選單底部現在是「**點我選服務**」——
   換成「**點我綁定，約診提醒不漏接**」會讓每一次打開聊天室都提醒一次。
   ⚠ 那是選單的一部分，要和第十節那個「六格換成嘴形」一起做。
2. **分頁式選單**（兩家都是兩個 tab：最新活動／服務專區）——
   芳仁六格夠用，**不需要**。記著這個做法存在就好。

### 13-4　沒有學的

emoji 一大串（🎉💛💰💳❗）、「好處多多」「懶人福音！」「不漏接！」這種促銷腔、
以及用顯示名稱開場。**都在 COPY.md 第三節那條紅線裡。**

### 14-4　⚠⚠ 第一名的缺口：**②「第一次提醒」，而且它不是新功能**

**它就是把現在那一則拆成兩次送。** 為什麼它值 77 分、和第一名只差 1 分：

1. ⚠⚠⚠ **它是那個結構性矛盾（第 8-1 節）唯一真正的解。**

   而提醒**剛好在 48 小時發** —— 卡片送到他手上時，期限**就是那一刻或已經過了**，
   上面卻掛著一顆「不克前往，預約改期」。**系統在期限那一刻遞給他一顆違規的按鈕。**
   文案怎麼寫都補不了這件事，只有時機能補。
2. **它會把電話分散開。** 現在所有想改約的人都被擠在最後兩天，

3. **兩次的話要說的事完全不同** —— 這一點決定它值不值得做：

   | | 看診前 3~4 天 | 看診前 48 小時 |

   | 這一則在問什麼 | **「這個時間還可以嗎？」** | **「別忘了」** |
   | 主要動作 | 要改就趁現在（還在期限內） | 記下時間、準時到 |

⚠ **這一條要廠商改排程，診所後台改不到**（做得出來只有 5 分）。
但它是這份清單裡**唯一一件能同時改善病人體驗、降低電話量、又解掉一個矛盾**的事。

**⚠⚠ 聊天室截圖裡的一則東西，先問「它是怎麼來的」，再問「它說了什麼」。**
LINE 的聊天室會把四種完全不同的東西畫成同一種泡泡：
主動推播、自動回應、選單觸發的回覆、真人手動回覆。
**畫面上分不出來。** 分不出來就**問**，不要從泡泡顏色推。

使用者問的是「你們從哪裡得到這個資訊的」，我就只去查那個資訊的來源，
沒有退一步問「這個東西的類別是不是一開始就搞錯了」。

## 十五、2026-09-02：提醒要不要拆兩次 —— **使用者說拆兩次要花錢，問能不能就提前到 4 天前**

### 15-1　先講一件會省錢的：**四則裡只有提醒卡要錢**

LINE 官方帳號的計費只算**主動推播**。**回應類的訊息不計入則數** ——
招呼訊息（加好友觸發）、自動回應（病人打字觸發）、關鍵字回應（綁定成功觸發）
**三則都是回應類，發幾次都不用錢**。

⚠ 只有**約診提醒**是系統主動送出的，那一則才計費。
⚠ **具體的級距與單價請在後台確認**，方案會變，我不引數字。

→ **所以「拆兩次要花錢」這個顧慮完全成立，而且它只針對第四則。**
前三則要改幾次、寫多長，都不影響帳單。

### 15-2　⚠⚠⚠ 但「提前到 4 天前」救不了，原因不是天數不夠

**協議是用「開診日」算的，排程是用「曆日」算的 —— 兩把尺不一樣。**

協議：看診日的**兩天前（不含假日）** ＝ 往回數 **2 個開診日**
（站上門診表只列一到五，所以週六日不算）。

拿 2026-09-07 那一週實算（`timing.mjs`）：

| 排法 | 晚於期限 | 落在休診日 | 結論 |
| --- | ---: | ---: | --- |
| **現況 48 小時**（＝2 曆日） | **2／5** | **2／5** | 週一週二的約診，提醒比期限晚兩天；其餘三天**剛好就是期限當天** |
| **提前到 4 曆日前** | 0／5 | **2／5** | ⚠ 不晚了，但週三週四的約診會在**週六、週日**送出 |
| 提前到 5 曆日前 | 0／5 | **2／5** | 同上，只是換成週四週五的約診踩到 |
| **✅ 3 個開診日前** | **0／5** | **0／5** | **五個看診日全部在期限之前，而且全部落在診所有開的日子** |

⚠⚠ **「落在休診日」為什麼要緊**：提醒上寫的是「打電話給診所」，
而**那天診所沒開，他打不通**。他得記到下一個開診日再打 ——
對週三的約診來說，下一個開診日就是週一，**正好是期限當天**，等於繞回原點。

⚠⚠⚠ **通則：任何固定的「幾天前」都一定會有幾天踩到休診日**，
因為曆日的週期是 7、開診日的週期是 5。**要真的解掉，排程本身要用開診日算。**

### 15-3　所以只有一則的話，正解是「**3 個開診日前**」，不是 4 天前

- 它**不用多花一毛錢** —— 同樣一則，只是換一個算法。
- 它讓提醒永遠**比期限早一個開診日**，那顆「不克前往，預約改期」
  **從邀請違規變成合法的出口**（第 8-1 節那個結構性矛盾就此解掉）。
- 它讓想改約的人**提前一個開診日**打電話，電話從最後兩天分散開。

⚠ **前提是廠商能用「開診日」排程**，不是只能填「幾小時前 / 幾天前」。
**這一題要先問**，問到之前不要假設做得到。

### 15-4　⚠ 但要知道它換掉了什麼：**防爽約**

一則的話，這是一個**真正的取捨**，不是純賺：

| | 3 個開診日前 | 現況 48 小時 |
| --- | --- | --- |
| 這一則在問什麼 | 「這個時間還可以嗎？」 | 「別忘了」 |
| 守不守得住協議 | ✅ | ❌ |
| 診所有沒有開（打得通電話） | ✅ 5／5 | ❌ 2／5 沒開 |
| **防爽約** | ⚠ **變弱** —— 週一的約診等於**提前 5 個曆日**提醒，離看診還很遠，看完就忘 | ✅ 48 小時是防爽約最好的時機 |
| 那顆「確定會到」 | ⚠ 提早問，回答的參考價值下降 | 比較準 |

### 15-5　⚠⚠ 決定這件事的是**一個我們沒有的數字：爽約率**

- **爽約很少** → 提前到 3 個開診日前，一則就夠，不必花錢。
- **爽約是個問題** → 這就**不是「要不要花錢」的問題，是兩種成本在比**：

      一則推播的錢　vs　一個空掉的診次

  一則推播是零點幾塊的量級；一個爽約的診次是**幾十分鐘的診療椅
  ＋ 醫師與助理的時間**。⚠ **兩邊差三到四個數量級**，所以只要拆成兩則
  能擋下**很小一部分**的爽約，它就付得起自己。
  ⚠⚠ **這個算式的數字要診所自己填** —— 我沒有爽約率，也沒有你們的推播單價。

### 15-6　第四條路：**改協議，不改系統**（免費，但要診所自己判斷）

讓 48 小時提醒失效的，是協議裡那三個字：**「不含假日」**。
拿掉它（改成「兩個曆日前」），現在的 48 小時提醒**當場就合法了**，
一毛錢不用花、廠商也不必動。

⚠ **但那三個字很可能是有理由的**：櫃檯要有**工作日**才補得到空出來的診次 ——
週六日取消，沒有人能打電話補位，那個診次就真的空掉了。
**所以這條路我不建議，但要列出來讓診所自己判斷** ——

## 十七、⚠⚠ 2026-09-02：滿意度調查卡 —— **它已經在跑了，而且有一個要先問清楚的風險**

### 17-3　⚠⚠⚠ 要先問清楚的一件：**這是不是「評論篩選」**

那兩個選項把人分成兩條路：**願意 → 分享體驗**、**不願意 → 提供建議**。

⚠ **如果「願意並分享體驗」是連到 Google 評論，而「不願意」是連到私下的表單，
那就是典型的 review gating（只向滿意的人索取公開評論）** ——
**據我所知這是 Google 商家檔案明文禁止的做法**，理由是它會讓公開評分失真。

⚠⚠ **但我不知道那兩顆按鈕實際去哪裡，所以這是「要問」不是「你們違規了」。**
（我今天已經因為從截圖推論錯了兩次，這一次先問。）

**要問的：**
1. 「👉願意並分享體驗」點下去到哪裡？Google 評論？還是診所自己的表單？
2. 「不願意並提供建議」點下去到哪裡？
3. 兩條路是不是**只有一條**通向公開評論？

**如果答案是「是」，這一條的優先度高於所有美感問題** ——
輕則評論被 Google 移除，重則影響整個商家檔案，
而商家檔案是這間診所最大的入口（六個月 14,973 次瀏覽、1,886 通電話）。

**合規的做法只有一種形狀：不要先問、不要分流。**
所有人拿到同一個邀請，想寫的自己會去寫；私下的意見管道**另外給、給所有人**，
不要當成「不滿意的人才走這條」。
⚠ 這個改法**同時解掉品牌問題** —— 現在這張卡是整個帳號裡最像推銷的一則，
而站上的紅線第一條就是「不推銷」。

### 17-4　⚠⚠ 第二件（和提醒卡是同一個結構問題）：**讀的人不是病人本人**

這張卡送到 **林苡馨（丞睿阿嬤）** 的帳號，開頭卻寫 **「親愛的 王丞睿，您願意推薦…」**。
**那個「您」指的是王丞睿，可是讀這則訊息的是阿嬤。**

⚠⚠ 這不是筆誤，是**結構性的**：這個診所**一個帳號綁多位家人是已確認的事實**
（第 7-3 節、第八節）。阿嬤帶孫子、媽媽帶小孩、子女幫爸媽約 ——
**「親愛的 ○○○，您…」這個句型在這間診所本來就會錯。**

**→ 立一條規則：這個帳號的每一張卡，都要假設「讀的人不是病人本人」。**
病人的名字要當**受詞**（那一次看診是誰的），不要當**稱謂**（在跟誰講話）。

⚠ 這和第 7-2 節替提醒卡定的改法**是同一條** ——
提醒卡是「〔姓名〕提醒您」讀起來像那個人在提醒你；
這張是「親愛的〔姓名〕，您…」把讀的人和病人混成一個。
**兩張卡要一起改，改法同源。**

⚠⚠ **不用 U+2009／U+200A 那種細空格**：它們要看系統字型有沒有那個字（卡片是 LINE 用

Flex 那邊對應的是 `span` 的 `size`，所以那兩句從 `text` 改成 `text` ＋ `contents[span]`：

```json

  { "type": "span", "text": "歡迎加入芳仁牙醫的官方" },
  { "type": "span", "text": " ", "size": "9px" },
  { "type": "span", "text": "LINE" } ] }
```

⚠ **`span` 裡的 `\n` 要跟廠商驗一次** —— 文件說 `wrap: true` 時 `\n` 是換行，
但我們沒有實機測過（綁定那一句同時有小空格和換行）。

   把空格整個刪掉照樣過關。補了一段專門驗這件事的（要有 span、要指定 size、
   要比內文小、要緊接在 `LINE` 前面、JSON 與提案頁的 px 要一致）。
   三種壞法都負面測試過：拿掉空格／不縮小／改回一整段 `text`。
2. **逐字量行數的程式要把空格排除**。那個小空格的字級不同，`rect.top` 就不同，
   按 `top` 分組會把它算成**多一行**。頁面裡的量測本來就有濾掉空格，

> `getBBox()` 回的是**元素自己座標系**裡的框 —— 對 `<g transform>` 呼叫它，

1. ⚠⚠ **百分比的 `max-width` 下在泡泡上，量出來的可用寬度會塌。**

⚠ **通則：兩個管道看起來打架時，先問它們是不是同一個動作。** 不是的話，
