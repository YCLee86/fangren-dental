### 一之二、標題與整篇的視角換過一次（2026-09-19 第二輪）

使用者：「這樣感覺比較不是和廠商合作關係，我們不要和廠商製造對立。比較像是
**懂得怎麼運用工具的醫師，讓這個新科技的工具用起來更順暢、病患體驗更好、
發揮這個工具的價值**，也符合創新、精準、人本醫療的意義。」

標題 `隱形矯正：電腦跑得順，牙齒不一定跟得上` → **`隱形矯正：模擬之後，醫師怎麼讓牙齒走得準`**。
舊標題把電腦與牙齒擺成兩邊，讀起來像在說工具不準；新標題的主詞是醫師，
「走得準」對上「精準」，而且沒有任何一方被踩。

⚠ **換標題不是只換那一行。** 同一輪跟著改的五處（不改的話標題和內文會各講各的）：

| 位置 | 改成 |
| --- | --- |
| 小標「模擬畫面上看不到的三件事」 | 「模擬畫面之外，**醫師還要看的**三件事」 |
| 「⋯**軟體排出來的**某一副會要求比較大的移動量」 | 「⋯**分期就會出現**移動量比較大的一副」（主詞不要是軟體在找碴） |
| 「模擬是規劃，不是結果」那一段 | 後面補一句「把這份規劃走成結果的那一段，是醫師在療程中一副一副對照出來的」 |
| 醫師小叮嚀 | 先肯定工具（「把規劃好的力量穩定地傳到牙齒上，透明牙套做得很好」），再講醫師補的是什麼，收在病患的好處（「愈早發現，要補回來的路愈短」） |
| lede 收尾、重點整理第一題 | 「誰來處理」寫明是「醫師在療程中怎麼對照與調整」 |

`<title>`／`og:title`／`post-meta` 的 `title`／`<h1>` 四處一起換，
`description`／`og:description`／`excerpt` 也重寫成同一個視角。
版面實測：新標題在 375／390 是兩行（67px）、834／1440 兩行（96px），四個視窗都沒有水平捲動。

⚠ **這一條是整篇的視角，不只是標題**：日後再改這一篇，
**不要寫成「軟體不準、醫師來救」**。要寫的是「工具把力量傳得穩，醫師讓它走得準」。

### 二之三、外連的樣式：`assets/style.css` 加了一條（會進正式站）

```css
.post-body a[href^="http"]::after { content: '\2197'; … }
```

・**站內連結一律是相對路徑**，所以 `[href^="http"]` 只會命中外連。
・加進來的當下，**十四篇文章的內文一條外連都沒有** —— 首頁、`posts/orthodontics/`、
  `topics/ortho/` 三頁實測命中數都是 **0**，對既有頁面完全沒有作用。
・**顏色一顆都沒新增**：箭頭吃 `currentColor`，跟著連結自己的色走，
  夜間模式不必另外寫（實測白天 `rgb(49,99,127)`、夜間 `rgb(104,151,181)`，
  都是 NIGHT 區塊裡本來就定好的那一組）。`node tools/night-mode.mjs --check` ✓ 全部一致。
・箭頭用 `::after` 產生、不寫進 HTML —— 寫成文字節點的話首頁那支搜尋會把它算進內文。
・七條都是 `target="_blank" rel="noopener"`：讀者點研究不會把文章弄丟。
  ⚠ 這是站上第一次用 `target="_blank"`（頁尾的地圖連結只有 `rel="noopener"`）。
