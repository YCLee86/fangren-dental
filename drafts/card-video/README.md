# 〈隱形矯正〉那張圖的動態 → 可以直接貼到臉書的 MP4

2026-09-22。使用者問「這種的正式名稱叫什麼呢　在臉書貼文上怎麼處理才能也正常顯示」，
接著指定「直接做：用站上那顆 Chromium 把卡片錄成 1080×1080、3.4 秒無縫循環的 MP4」。

**成品刻意不放在網站上**（同 `drafts/door-notice/`）——
這是要上傳到臉書的檔案，站上那一份動態是 CSS，兩者不是同一個東西。

```bash
node drafts/card-video/card-video.mjs            # 兩個尺寸都出
node drafts/card-video/card-video.mjs --only sq  # 只出方的
node drafts/card-video/card-video.mjs --keep     # 保留逐格 PNG（除錯用）
```

| 檔案 | 尺寸 | 用在哪裡 |
| --- | --- | --- |
| `out/aligner-1080x1080.mp4` | 1080×1080・141 KB | 臉書動態的方形影片貼文 |
| `out/aligner-1080x602.mp4` | 1080×602・142 KB | 原圖比例，一個像素都沒加沒裁 |

兩支都是 **H.264 / yuv420p / 30fps / 3.4 秒 / 無聲軌 / `+faststart`**。

---

## 一、為什麼要做成影片（而不是「把網站的動畫貼過去」）

站上那個動態**不是一種圖片格式，是程式**（CSS `@keyframes` ＋ SVG 疊層，
圖檔本身仍是普通的 JPEG／WebP）。臉書不會執行別人網站的 CSS，所以要在臉書上動，
就得先把它「凍成一格一格再接成影片」。

分享**網站連結**到臉書是另一回事：那張預覽卡吃的是 `og:image`，
**永遠是靜態 JPEG**，所有平台都一樣，沒有辦法讓它動。

三種格式比過：**MP4 最好**。GIF 上傳之後臉書還是會轉成影片
（同一段 4 秒實測 GIF 9,842 KB 對 WebM 354 KB，付了檔案大、畫質差的代價卻沒有回報）；
動態 WebP／APNG 臉書不會播，只顯示第一格。

## 二、⚠ 唯一一處和站上不同：警告標示 2 秒 → **1.7 秒**

站上兩件動的東西是 **驚嘆號 3.4 秒**、**警告標示 2 秒**。
要兩者同時回到原點，最短得剪到 **34 秒**（3.4 與 2 的最小公倍數）——
臉書上沒有人會看 34 秒。改成 1.7 秒之後剛好 2 個週期 ＝ 驚嘆號的 1 個週期
＝ **3.4 秒完美無縫**。

⚠⚠ **這個值只屬於影片。** 站上那個 2 秒是使用者 2026-09-21 逐項挑的
（「速度都用中」），**不要拿 1.7 回頭去改它**。

## 三、⚠ 動畫的規格不在這一支裡

`card-video.mjs` 把 `posts/aligner-simulation/index.html` `<head>` 那段
`style#hero-fx-css` **整段照抄**（連 `.post-hero` 的選擇器前綴都留著，
所以頁面上那個 `<figure>` 也照抄），只覆寫上面那一行週期。
**規格只有一份**，和 `tools/card-motion.mjs` 同一條紀律 ——
在這裡另外調速度或幅度，兩邊遲早會不一樣。

## 四、逐格是**凍出來的，不是錄出來的**

整頁的動畫全部 `pause()`，再逐格把 `animation.currentTime` 設成那一格的時間。
螢幕錄影會受排程與掉格影響，出來的循環對不齊，接點會抖一下。

⚠ 驚嘆號各自有 0.28 秒的錯開，而 Web Animations 的 `currentTime` **本來就含延遲**
（進度 ＝ currentTime − delay），所以五顆設同一個值就自動錯開，**不要自己減**。

⚠ 一定要把頁面寫成真的檔案再 `goto`，**不可以 `setContent`** ——
`setContent` 的文件網址是 `about:blank`，那個來源載不到 `file://` 的圖，
症狀是兩張圖都 `naturalWidth` 0、截出來一片空白，**而且不會報錯**。

## 五、四道守門（都負向測過）

1. **接點**：另外畫一格 `t = 3.4s`，必須和第 0 格**逐位元組相同**。
   ⚠ 這一道最強 —— 把週期改回站上的 2 秒，它立刻擋下來（實測過）。
   算得出來不算數，要量畫出來的東西。
2. **反向**：第 0 格和四分之一處**不可以**相同（不然是一支靜止的影片，第 1 道照樣會過）。
3. **圖**：一定要兩張（主圖 ＋ 疊層）、`naturalWidth ≥ 1080`、而且**兩張是同一個檔**。
4. **動畫數**：`document.getAnimations()` 必須是 6（5 個驚嘆號 ＋ 1 個警告標示）。

## 六、⚠ 版面：為什麼方的那一版留了白，沒有裁成滿版

這張圖是 16:9（2000×1114），硬裁成正方形會切掉**左邊的工程師與右邊的兩位同仁** ——
那正是這張插畫在講的事（掃描 → 模擬 → 醫師判斷 → 說明給病人）。
所以方的那一版是「圖照原比例 ＋ 上下放診所識別」，不是裁切。

⚠ **圖上的字只能用 `tools/fonts/glyphs.txt` 裡有的**：容器裡沒有中文字型，
用的是子集化過的 Noto Sans TC，不在表裡的字會掉到文泉驛正黑（和站上不是同一套）
**而且不報錯**。「隱」「形」不在表裡，所以圖上寫的是**科別**「齒顎矯正」
而不是文章標題。要加字得先補 `glyphs.txt` 再重跑 `pyftsubset`
（見 `tools/og-plate.mjs` 檔頭）。腳本裡有一道守門會逐字檢查。

## 七、⚠ 貼的時候會撞到已經定案的臉書版面

使用者 2026-09-09 定的臉書成品是**三張 1080 方圖拼成一顆標誌的相簿三格貼文**
（LINE.md 第三十八節）。**影片放不進那個三格**（一則貼文不能圖片影片混排），
相簿也是放照片的。所以這支影片只能是**另外一則獨立的影片貼文**。

## 八、還沒驗證的（容器連不出去，要使用者貼一則才知道）

- 臉書動態上的短影片會不會自動重播（循環）。
- 方形影片在動態上實際佔多寬（既有那三張照片量到的是滿版 100%）。
