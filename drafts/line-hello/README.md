## 二、⚠⚠ 顏色：深階 `#2c5238`，不是套色 `#3f654a`

使用者說「一般牙科主題色」，那一支有兩階。量下來**深階明顯較好**，而且理由和
站上的規矩一致：**深階給亮底上的字，套色給填實的塊**。

| | 套色 #3f654a | 深階 #2c5238 |
| --- | ---: | ---: |
| 筆畫底下對比低於 4.5 的像素 | **11.0%** | **2.1%** |
| 低於 3 的 | 1.8% | 1.1% |

（M PLUS 那一張的數字；其餘三支字體同一個方向：套色 8.8~12.5%、深階 1.5~3.4%。）

### ⚠⚠⚠ 這一輪算錯兩次才算對

這顆綠是**中間調**（套色 L\* 39.3、深階 L\* 31.5），所以壓在照片上的最壞情況
**既不是背景最亮處、也不是最暗處，是「背景剛好和它一樣亮」的那些像素**。

1. 第一版量「最亮處的對比」—— 對深色字來說那是**最好**的情況，數字漂亮但沒有意義。
2. 第二版改量「最暗 2%」—— 也錯：背景全黑時綠字反而看得很清楚（對比 3.17）。
3. 第三版才對：**算「有多少比例的像素對比不足」**。

**通則：中間調的顏色壓在照片上，不能只看一個極值 —— 要算不合格的比例。**
（近親：ILLUSTRATION.md 第十二節七科線稿的臨界濃度，也是每一科現算一次。）

## 四、字體

參考圖的特徵：幾何、等粗、端點全圓、字重很重。Google Fonts 上四支候選：

| | 字重 | 不合格（深階） | 備註 |
| --- | --- | ---: | --- |
| **M PLUS Rounded 1c 900** | 最接近參考圖的結構（幾何、等粗） | 2.1% | **建議** |
| Zen Maru Gothic 900 | 較細、較開，比參考圖柔 | 1.5% | |
| Baloo 2 800 | 最重、字腔最小，比參考圖更「圓潤」 | 3.4% | |
| Fredoka 600 | 幾何圓體，比參考圖寬一點、親切一點 | 2.3% | |

### ⚠⚠ 中文「你好」是**近似**，不是真的圓體

**M PLUS Rounded 1c 與 Zen Maru Gothic 都是日文圓體，實測「你」不在它們的字集裡**
（只有「好」）—— 出圖前用 fontTools 讀 cmap 驗出來的。
**Google Fonts 上沒有圓體的繁體中文。**

所以「你好」用 **Noto Sans TC 900 ＋ 一圈同色的圓角描邊**（`paint-order: stroke fill`
＋ `stroke-linejoin: round`）去逼近。描邊 3px；7px 試過，**900 的中文本來就滿，
字腔會被塞死**。另出一張完全不描邊的當對照 —— 乾淨，但就不圓了。

⚠ **要真的圓體中文，得買字（例如源流圓體之類的商用圓體），這一份做不到。**

## 五、量測方法（下次換照片要重跑）

判準是**「字的筆畫底下那些像素」對比不足的比例**，不是整塊區域的平均。做法：

1. 黑底白字、沒有照片 → 截一張當**遮罩**
2. 只有照片、沒有字 → 截一張當**背景**
3. 遮罩亮度 > 200 的那些位置，取背景同位置的顏色，算它和綠字的對比度
4. 統計低於 3 與低於 4.5 的比例

⚠ 報表裡的「最低 1.00」是**筆畫邊緣的抗鋸齒像素**，每一張都會有，沒有意義 ——
要看的是比例不是最低值。

⚠ 出圖有一道守門：筆畫像素少於 2000 就 throw（字沒畫出來、掉字、或字型沒載到時
瀏覽器會靜靜地掉到系統字，不報錯 —— 同 `rich.mjs` 那道字集守門的理由）。

## 六、提案頁的切換條：三軸完整交叉

**文字（2）× 字體（4 或 2）× 顏色（2）＝ 12 格，每一格都真的有一張圖。**

⚠⚠ 中間做過一版有「大小」那一軸，但只有 M PLUS 出了三個尺寸，其餘字體按小／大
**會回到同一張圖 —— 那就是這一站踩過很多次的「按了沒反應」**（第九節第 24、25 條）。
一度改成「按了就把其他軸帶到合法組合」，結果變成按「小」會從你好跳回 hello，更糟。
**最後把那一軸整個拿掉**（它本來就是我加的，不是使用者要的），改成三軸完整交叉。

**通則：切換條上按得下去的每一格，按下去都必須換到一張不同的圖。**
驗收方式是腳本逐格按一次，比對「按下去的狀態」和「換到的檔名」——
12 格換到 12 張不同的圖才算過。

### 8-1　⚠⚠ 左邊和下面**不能各自調**

高度那一刀要**從上下分配**：全部從下面切會吃到騎樓（建築底部在 y 88%）。
所以每一案其實是三個數字連動，不是兩個獨立的滑桿。

### 9-3　三道守門（這一輪新加的）

`generate.mjs` 出每一張圖時都驗，過不了直接 throw：

1. **宣告了玻璃，就要量得到提亮** —— 不然是 `backdrop-filter` 被瀏覽器靜靜忽略，
   畫面看起來只是一塊平白的方塊，不報錯。
2. **宣告了模糊，起伏就要真的降下來**（量遮罩邊緣那一圈的標準差降幅）。
3. **字在聊天室不得小於 11px**（設計稿 × 0.223）。

實測：淡 +0.076／降 43%、中 +0.146／降 54%、濃 +0.216／降 57%，字 19.6px。

⚠ 量「有沒有生效」要取**遮罩邊緣那一圈**，不要取整塊 —— 中央被字佔掉，
把字算進去會讓亮度統計失真。

## 十、2026-09-03：**字加大 ＋ 手繪對話框**（房子在說話）

> 「感覺可以字再大一點，然後像這張照片用手繪的感覺，在建築拉一個對話框，
> 像是房子在說 芳仁哩厚 的樣子。對話框線條顏色跟字一樣，位置也要注意一下。」
> （參考圖：YEBISU GARDEN CINEMA 的燈箱，白色手繪線條的人形壓在照片上）

字 88 → **104px**（在聊天室裡 19.6 → **23.2px**）。
對話框自己畫（`drafts/line-hello/bubble.mjs`），框線 `#2c5238`，和字同色。

### 10-1　為什麼自己畫

⚠ 診所的標誌本來就是**圓潤的有機形狀**，對話框走同一套語彙才不會外來。
做法：圓角矩形取樣 → 用兩個低頻正弦沿法線推一點點（振幅 5px）→
Catmull-Rom 轉三次貝茲 → 尾巴的尖端設成「角點」（控制點收回自己身上，轉角才是尖的）。

⚠ **不要畫得太抖**：參考圖那些人形是很肯定的一筆，不是顫抖的線。

### 10-2　位置：尾巴要指到房子，而且不能穿過紅招牌

在成品的 1040×520 座標裡疊格線讀出來：

| | 位置 |
| --- | --- |
| 診所外牆右緣 | x ≈ 430（y 100~390） |
| 屋簷右尖 | (440, 90) |
| **劉家那支紅招牌** | **x 620~660、y 165~325** |
| 右邊灰樓的牆 | x 700~960 |
| 遮陽棚上緣 | y ≈ 360 |

定案：框 **x 468~812、y 18~318**，尾巴尖端 **(432, 352)** ——
落在清水模外牆的右下，讀起來就是這棟房子在說話。
⚠ **框只能放建築右邊、不能放更右邊**：放右邊的話尾巴會穿過紅招牌。

量測：對話框那條線 12,732 個像素逐點量，**只有 3.3% 壓在對比不足的地方**。

### 10-3　⚠⚠⚠ 玻璃這一段連踩兩個坑，兩個都不報錯

**坑一：`backdrop-filter` ＋ `clip-path` 放在同一個元素上，模糊會被丟掉。**
白色上得去（框裡亮度 +0.056），但起伏 **0.0636 → 0.0637**，一點都沒降。
這是 CLAUDE.md 第九節第 20 條那一類（被裁切的東西上面再掛濾鏡，瀏覽器靜靜地不畫）。
→ 改成**外層只負責裁切，裡面放一份同樣位置、自己 `filter: blur` 的照片複本**，再疊一層白。

**坑二：改好之後仍然量到「0% 降幅」，但這一次是判準錯不是實作錯。**
另外做了一張探測圖，紅招牌明顯糊了 —— 模糊一直有生效。
成因是 **RING 落在平滑的天空上，而模糊不會改變平滑漸層的起伏**。

⚠⚠ **通則：模糊要在有紋理的地方量。** 平滑的漸層模糊前後幾乎一樣，
拿它當判準會得到「沒生效」的假警報，然後把好的實作改壞。

→ 現在拆成兩件各自量：
1. **模糊**：開／關兩張圖在對話框範圍內的**平均差**（一次性，量到 5.6 階，門檻 1 階）
2. **白底**：RING 的亮度提升（每一案：淡 +0.055／中 +0.098／濃 +0.138）

### 10-4　量測基準也修過一次

原本拿「只有照片」那一張當基準，量出「不加玻璃卻起伏變大 124%」這種鬼數字 ——
因為 RING 不管放哪都會沾到框線或字的邊，那些**靜態內容被算成了玻璃的效果**。
→ 改成拿**同一支字體、不加玻璃**那一張當基準，靜態內容自動抵銷。

**通則：比較用的基準要和被測的那一張「只差一個變因」。**

### 10-5　線的粗細也要 ×0.223

框線 10px → 在聊天室裡 **2.2px**。守門設在 1.5px，太細會看不見。
（同字級那條：設計稿的尺寸乘 0.223 才是病人真正看到的大小。）

### 10-6　2026-09-03 再一輪：**框太擠、尾巴太長**

> 「感覺對話框和房子有點擠，那個房子講話的延伸角形拉好長好怪。」

兩件都成立，而且都是量得出來的：

| | 原本 | 改成 |
| --- | ---: | ---: |
| 框離外牆右緣（x≈430） | **38px** | **82px**（框 x468 → x512） |
| 尾巴長度 | **148px** | **70px** |
| 尾巴根部寬（周長比例） | .055 | **.075** |

⚠⚠ **148px 那根本不是對話框的尾巴，是一根刺。** 成因是尾巴原本用**絕對座標**
指定尖端（`tipX/tipY`），長度是算出來才知道的 —— 寫的時候看不出來。
→ `bubble.mjs` 的尾巴改成 **「長度 ＋ 角度」**（`len` / `angle`），
一眼就看得出來寫了多長。

**通則：參數要用「你在判斷的那個量」表示。** 判斷的是長度，就不要用端點座標。

九組試過（離房子 38／82／126 × 尾巴 45／70／95）才定這一組。

### 10-7　⚠⚠ 兩個「跟著別人動、卻寫死」的東西

1. **RING 寫死座標** —— 框從 x468 移到 x512，量測區就落到框外面去了，
   量出「玻璃沒有提亮」的假警報。→ 改成從 `BUBBLE` 推算。
2. 順手加的守門：**尾巴的包圍盒不可以和紅招牌重疊**、
   **框離外牆至少 60px**、**尾巴不超過 90px**。

**通則：跟著別人動的東西，就要用別人算出來。** 這一輪與上一輪的假警報都是同一個病。

現在的數字：框線 11,415 個像素，只有 **2.4%** 壓在對比不足的地方；
模糊平均差 6.4 階；白底提亮 淡 +0.060／中 +0.105／濃 +0.148。

### 10-8　2026-09-03 再一輪：**兩行對調、線太粗像油漆**

> 「芳仁比較左邊、哩厚比較右邊，對調一下……那個對話框我覺得好粗，
> 比較不像手繪，很像油漆的感覺，能不能再可愛自然一點。」

#### ⚠ 兩行的錯位不是排版造成的

先量：兩行的**字面框完全對齊**（都是 216.3px 寬、中線偏差 0.0）。
看起來錯位是**字本身的墨色分布** ——「仁」右邊留白多、「厚」填滿整格。

所以要做的不是「修正對齊」，是**刻意的錯位排版**：芳仁 **+22px**、哩厚 **−22px**。

**通則：使用者說「這兩個東西沒對齊」時，先量一次。** 對齊的是框，看的是墨。

#### ⚠⚠ 「像油漆」的成因是**均勻的粗線**

一條粗細一樣的線，讀起來就是滾出來的；真的手繪，筆壓會變、線寬跟著變。

做法：把輪廓**切成 9 段，每段自己的線寬**（7px ± 34%），
`stroke-linecap: round` 讓接縫自然消失，轉折處還會有一點「疊筆」的味道。
另外 `wobble()` 加了一個高頻項（振幅只有 0.18 倍）當手抖。

實測 5.4~9.3px → 在聊天室 **1.21~2.08px、平均 1.57px**（原本是一律 2.23px）。
守門改成看**平均**（≥1.5px）與**最細**（≥1.1px），不再是單一定值。

#### ⚠⚠ 但光是線變細不夠 ——「可愛自然」有一半在**形狀**上

五組試過（現在的／更圓更抖／更圓線更細／最圓像塗鴉／錯開少一點），
定案 **圓角 86 → 118、抖動 5 → 11**。方框感消失，才讀得出是手繪的泡泡。

#### ⚠ 順帶踩到一個工具坑

`node generate.mjs | head -6` 會讓 `head` 提早關掉管線、**把產生器掐死在寫
`report.json` 之前** —— 圖出了但報表是舊的，提案頁上的線寬因此顯示 1.78px
（舊值）而不是 1.56px。

**通則：會寫檔的腳本不要接 `head`。** 要看前幾行就先導到檔案再看。

## 十二、2026-09-03：**圓角矩形與膠囊之間 ＋ 一筆畫最後的小缺口**

使用者的話：「介於圓角矩形和膠囊之間的形狀　風格要像這張照片下方的手繪對話框
**一筆劃最後帶一個小缺口**　比較有人畫的感覺　玻璃濃度是中」。

第十一節那一輪把「形狀」拆成四案讓他挑，這一輪他直接指定了形狀，
所以切換條的兩軸換成 **缺口大小 × 字體**（3 × 3 ＝ 九格）。

### 12-1　形狀：圓角 92 是算出來的，不是挑的

框是 344 × 288。**圓角矩形那一端 44、膠囊那一端 144**（＝高的一半，再大就不是圓角了），
中間就是 **92**。不必給候選案 —— 兩個端點都由幾何決定，「中間」只有一個值。

### 12-2　缺口：描邊改成**開放路徑**，底維持封閉

`bubble.mjs` 第三次改寫，拆成三支：

| | |
| --- | --- |
| `outline(o)` | 密取樣的點串（圓角矩形 ＋ 尾巴），**其餘兩支都吃它** |
| `closedPath(pts)` | `M … L … Z`，給**填色與玻璃的 `clip-path`** |
| `openPath(pts, gapFrac, startFrac)` | 給**描邊**，中間缺一段 |

⚠⚠ **底一定要維持封閉** —— 缺口只開在描邊上。填色也跟著缺一角的話，
玻璃會從缺口漏出去一塊，那不是「筆提起來」是「框破了」。

### 12-3　⚠⚠ 不要用「墨少了幾 %」判斷缺口夠不夠大

守門第一版寫成「描邊的墨要比封閉版少 gapFrac 那個比例」，三案全部過不了。
成因是 **`stroke-linecap: round`**：開放路徑的兩端各補一個半圓，
加起來約等於**一整個線寬**的墨。所以量到的減量永遠比名目少：

| 缺口 | 名目弧長 | 看得到（弧長 − 線寬） | 聊天室裡 | 墨真的少了 |
| --- | --- | --- | --- | --- |
| 小 | 31px | **24px** | 5.3px | 2.2% |
| 中 | 53px | **46px** | 10.3px | 3.9% |
| 大 | 83px | **76px** | 16.9px | 6.2% |

判準因此改成**眼睛真正看得到的那一段有幾 px**，地板 12px（再小就只是一個小缺角，
讀不出「筆畫沒接回去」）。

**通則：圓頭的筆尖會把缺口兩端各填回半個線寬。凡是「開一個口」的東西，
量的是看得到的長度，不是名目的長度。**

### 12-4　⚠⚠ 缺口**開在哪裡**，和它多大一樣要緊

第一版 `startFrac = .06`，算出來缺口落在**上緣正中央**（x 641，框心 684）——
對稱的位置讀起來像**印壞了**，不像有人畫到最後把筆提起來。

改成 `.16`：落在上緣、**右上圓角之前**（x 749，圓角從 764 起）。三個理由：
偏一邊；在一段長直線上（不吃掉圓角）；那一段的底是**乾淨的天空**，
縮到 232px 也讀得出來。

守門因此新增三條，而且是**實際去看那一段路徑落在哪裡**、不是重算一次幾何
（圓角或尾巴一改就會移位）：① 要在上緣的直線段上 ② 離框心 ≥ 40px
③ 兩端都要離尾巴根部夠遠。

### 12-5　⚠⚠⚠ `tail.cx` 是絕對座標，換算周長位置要先減掉 `x`

`outline()` 裡把尾巴插進點串時漏了 `- BOX.x`，尾巴被插到**上緣**去 ——
畫面上是一條斜線橫穿整個框，連玻璃的 `clip-path` 也跟著歪。

⚠ **原本的守門驗不出來**：它只驗「尾巴根部的 x 在框的範圍內」，而錯誤的位置
剛好也在範圍內。找出來的方法是**掃相鄰兩點的距離**——密取樣的點串相鄰距離
應該都是幾 px，出事的地方跳了 297px 與 335px（i = 53~56）。

補了兩道：① 尾巴的兩側必須接在**下緣**（檢查尖端左右兩點的 y）
② 相鄰兩點的距離不得超過 `max(80, 尾巴寬 + 40)`。

**通則：守門要驗「東西長對了沒」，不要只驗「參數在範圍內」。**

### 12-6　⚠ 產出檔改名，引用它的地方不會報錯

檔名從 `hero-<形狀>-<字體>.jpg` 換成 `hero-<缺口>-<字體>.jpg` 之後，
`preview/line-reply/` 那一頁指著已經被刪掉的 `hero-round-mplus.jpg`，

是刻意留著的裁切原圖，寫在 `KEEP` 裡）。**每次重跑 `generate.mjs` 之後跑一次。**
