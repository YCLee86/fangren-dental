## 二、先講**已經做對、不要動**的事

這些在同業裡是少見的，審這一輪的時候差點被我當成「還可以再加強」而動到手：

1. **結構化資料是全站最強的一塊（D 組 15.5/18）。** `@graph` 串 `@id`、
   看診時間與醫師名冊從畫面讀回來不重抄、`hasCredential` 只收部定專科、
   `og:image:width/height` 從 JPEG 檔頭算而不是寫死 —— 這些都做對了。
2. **⚠ 沒有加 `FAQPage`／`HowTo`／自評 `Review`，這是對的，不要因為「GEO 要結構化」而加回去。**
   Google 2026-05-07 起停止顯示 FAQ 複合式結果、8 月移除 API 資料；HowTo 2023 就下架；
   自評星等是明文禁止。這一站已經在 CLAUDE.md 第十節寫明，**這份報告完全同意**。
3. **文章的 answer-first 結構本來就很好。** 全站 95 個 h2 的第一段，
   **中位數 69 字、78% 落在 40–120 字的可擷取區間、超過 200 字的只有 1 段**。
   這正是 2026 被引用率最高的寫法，而且是自然寫出來的不是套出來的。
4. **15 篇文章篇篇有 `<dl class="keypoints">` 的問答式重點整理。** 這是 GEO 的理想形狀
   （問句 → 直答，段落自足），而且**不需要**配 `FAQPage` 標記也照樣被抓。
5. **圖片零缺失**：23 頁共 100+ 張圖，`alt` 覆蓋 100%、`width`/`height` 覆蓋 100%、
   WebP `<picture>` 就位、`alt` 是真的在描述畫面而不是塞關鍵字。
6. **在地實證內容（E4 滿分）**：停車格現地清查、門口地圖、周邊導航 ——
   這是 AI 回答在地問題時最會抓的那一種內容，而且抄不走。
7. **靜態 HTML、一頁一個網址、關掉 JS 內容還在**（CLAUDE.md 第一節第 1、2 條）。
   2026 年 AI 爬蟲多半**不執行 JavaScript**，這個決定現在的價值比當初訂的時候更高。

### ✅ ~~🔴 P1-1~~　七個科別著陸頁與 15 篇文章之間，**連結是單向的** —— 2026-09-20 已修

**現況**（`links.mjs` 量測）：

- 著陸頁 → 文章：有（每頁 1–4 篇）
- **文章 → 著陸頁：15 篇全部是零。** 文章的內部連結只指向 `/`、`/#topics`、
  `/#doctors`、`/#clinic` 與另外 5 篇文章。
- 文章的 `BreadcrumbList` 第 2 層指向 **`https://fangren.net/#topics`（首頁錨點）**，
  不是 `/topics/perio/`。
- 畫面上那一行麵包屑裡，科別是 `<span class="post-tag" data-spec="perio">`，
  **是 span 不是連結**。

**為什麼要緊**：`data-spec="perio"` 已經在那個 span 上了，也就是**對應關係早就知道**，
只是沒接起來。結果是七個專為 SEO 做的著陸頁，各只拿得到 8 個站內入口
（首頁 1 ＋ 七頁互連 7），15 篇文章一個都沒有回指。對爬蟲與 AI 來說，
這等於在說「這一篇的上一層是首頁」，七個著陸頁的 hub 地位建不起來。

**怎麼修**（兩處，都在產生器裡）：

1. `tools/build.mjs`：`BreadcrumbList` 第 2 層的 `item` 從 `https://fangren.net/#topics`
   改成 `https://fangren.net/topics/${SPEC[p.tag]}/`。`SPEC` 那張表就在同一支的第 513 行。
2. 文章模板的 `<p class="crumbs">`：把 `<span class="post-tag" data-spec="…">` 換成
   `<a class="post-tag" href="/topics/<spec>/" data-spec="…">`。
   ⚠⚠ **那一段確認在 `<main>` 裡面**（量過：`<main>` 在第 10870 字元、`crumbs` 在 10961），
   所以 **15 篇的內容雜湊會一起變**，`updated` 會全部跳成當天。
   照 CLAUDE.md 第五節的判準，這一種是「對讀者不算內容變了」（只是把科別接成連結），
   → **要照那個程序把 `build-manifest.json` 裡那 15 筆的日期改回去，再跑一次 build。**

**預估**：D3 從 1.4 → 3.0（15 篇各 +2 分），著陸頁的站內入口從 8 → 10～13。

### ✅ ~~🔴 P1-2~~　七個著陸頁：**h1 排在 h2 後面，而且唯一的獨有內容沒有任何標題** —— 2026-09-20 已修

**現況**：著陸頁是 `index.html` 的快照，所以文件順序是

```
h2 主題與科別      ← 首頁那一節的標題，先出現
  h1 牙周治療      ← 這一頁真正的標題，在它後面
  h3 …文章卡…
h2 醫師介紹
h2 診所資訊
```

而那一頁**唯一不與首頁重複的內容**（`.tp-intro`：三個病人的問句、一句回應、
五步流程、一句收尾）**整塊沒有任何 h2／h3**，全部是 `<p class="tp-case">`、
`<p class="tp-step"><b>檢查</b>…`。

**量出來的結果**：

| | 與首頁的文字重疊率 | 獨有的四字詞 |
| --- | --- | --- |
| `/topics/general/` | 77.0% | 44 |
| `/topics/kids/` | 76.8% | 42 |
| `/topics/prosth/` | 75.4% | 35 |
| `/topics/ortho/` | 75.2% | 35 |
| `/topics/surg/` | 71.6% | 31 |
| `/topics/perio/` | 69.7% | 43 |
| `/topics/endo/` | 68.1% | 38 |

七頁各有 **68–77% 的文字和首頁一樣**，獨有的部分只有 200–350 個中文字，
而且沒有標題可以讓檢索系統把它切成一個段落。

**為什麼要緊**：段落級檢索靠標題定界。沒有標題的 `<p>` 群，被切成 chunk 之後
夾在「主題與科別」和「醫師介紹」中間，很難被判定成「這一段在回答牙周治療是什麼」。
這七頁最有價值的東西（**病人真的會問的三個問題** ＋ **一條從檢查到維護的流程**）
正好是 AI 最愛引用的兩種形狀，現在卻是最抓不到的那一塊。

**怎麼修**（全部在 `tools/topics.mjs` 的 `introBlock()`，改完跑 `node tools/topics.mjs`）：

1. **讓 h1 排到最前面**，或把首頁那個「主題與科別」的 h2 在著陸頁降成
   `<p class="sec-label">`／`<h2 class="sr-only">`（它在著陸頁是導覽列不是章節）。
2. **三句 `.tp-case` 改成 `<dl>`**：`<dt>` 是病人的問句、`<dd>` 是那句回應。
   現在的「三個問句 ＋ 一句總回應」拆成三組問答，是這七頁最划算的一改。
3. **五個 `.tp-step` 改成 `<ol>`**，`<b>檢查</b>` 改成 `<li><strong>檢查</strong>…`。
   有順序的東西用有順序的標記。
4. `.tp-first-h`（「從檢查到維護，大概會這樣走」）**改成真的 `<h2>`**，
   它本來就是一個標題，只是現在是 `<p>`。
5. 順手補 `twitter:card`（七頁都缺，`seoBlock()` 裡加一行）。

⚠ 文字一個字都不用改 —— **這一項改的是標記不是文案**，所以不必回 COPY.md 重審。
⚠ 但第 1 項會動到版型，照 CLAUDE.md 第八節的規矩，這一項該先開一頁提案給使用者看。

### 🟠 P2-2　robots.txt 對 AI 爬蟲**沒有任何立場**

**現況**：

```
User-agent: *
Allow: /
Disallow: /history/
Disallow: /preview/
Disallow: /version.txt
```

也就是：**訓練型與檢索型的 AI 爬蟲一律放行**。沒有 llms.txt（這件事**是對的**，見下）。

**為什麼要緊**：2026 年的主流做法是**擋訓練、放檢索** —— 兩者是不同的機器人，
可以分開決定。目前這一份等於「全部同意」，不是壞事，但那**應該是使用者做的決定，
不是預設值**。這一項扣 2 分不是因為做錯，是因為沒有選過。

**兩個選項**（要問使用者）：

| | 做法 | 換到什麼 |
| --- | --- | --- |
| **甲（維持現況）** | 什麼都不改 | 內容可能被拿去訓練；在所有 AI 的回答裡都可見 |
| **乙（擋訓練、放檢索）** | `Disallow` 給 `GPTBot`／`ClaudeBot`；`Allow` 給 `OAI-SearchBot`／`ChatGPT-User`／`Claude-SearchBot`／`Claude-User`／`PerplexityBot`。**`Google-Extended` 另外決定**（見下） | 一樣被引用，但不進 OpenAI／Anthropic 的訓練資料 |

⚠⚠ **不要擋錯邊。** 擋掉檢索型的那幾支，等於從 ChatGPT／Claude／Perplexity 的
回答裡整個消失。
⚠⚠ **`Google-Extended` 這一支要單獨想。** 它**不影響** AI Overviews 與 AI Mode
（那兩個吃的是一般的 Googlebot 索引，不看這支），但它管的**不只是訓練** ——
Gemini 的 grounding（即時抓網頁來回答並附上出處）也吃它。
**擋掉它 ＝ 訓練停掉，但 Gemini 的引用也一起沒了。** 所以「乙案」要不要把它放進去，
是一個獨立的取捨，不能和 `GPTBot`／`ClaudeBot` 綁在一起決定。

⚠ robots.txt **每次 build 整個重寫**，要改請改 `tools/build.mjs` 裡的產生字串
（CLAUDE.md 第四節）。

**✅ 順帶：llms.txt 不要做。** Google 公開說不支援也沒有計畫；
Ahrefs 掃 13.7 萬網域，**97% 的 llms.txt 在 2026-05 整個月零次請求**。
它真正的用途是**餵寫程式的 agent**（Cursor、Claude Code 讀它），對這一站沒有意義。

### 🟠 P2-3　首頁與七個著陸頁，**每一頁都夾帶 175KB 的內嵌 CSS 與 JS**

**現況**（上線版，已去註解）：

| --- | --- | --- | --- |
| `/` | 261KB | 73.5KB | 116.3KB |
| `/topics/<spec>/` ×7 | 209–217KB | 73.8KB | 101KB |
| `/posts/<slug>/` ×15 | 23–41KB | 0 | 5–7KB |

文章頁很漂亮（23–41KB）。問題在首頁與七個著陸頁：**同一份 73.8KB 的 CSS 與
101KB 的 JS 被複製了八次**，而且因為是內嵌的，**跨頁完全不能快取** ——
使用者從首頁點進 `/topics/perio/`，那 175KB 要再下載一次。

**為什麼要緊**：直接打在 LCP 上（主執行緒要先解析完才畫得出東西），
也吃掉爬蟲的抓取預算。這是 F 組只拿 4/8 的主因。

**怎麼修**（由小到大，建議只做第 1 項）：

1. **把 101KB 的內嵌 JS 抽成 `assets/app.js`**（`defer`）。八頁共用一個檔，
   第二頁起是快取命中。⚠ 那裡面有一段是**開頁就要跑**的（著陸頁捲到 `#topics`
