起因

使用者：「電腦版上看現在的首頁效果很好因為是滿版的，但是手機上看那個照片他就
縮小了，感覺那個效果或那個感覺就沒有像電腦版那麼好。根據網站使用者體驗還有品牌
顧問的規劃評分看看，或是還可以從照片資料庫裡面找一張放在這邊，然後設計建議給我
看一看。」

一、問題不在照片，在框的形狀

手機的 .hero-photo 寫死 74.72vw。實測：

    視窗        照片高    佔一屏   詩的字級
    320x568     239px      42%      9.79px
    375x812     280px      35%     11.48px
    390x844     291px      34%     11.50px
    430x932     321px      34%     11.50px
    電腦 1440   900px     100%     15.00px   <- 使用者說「效果很好」的那個

一棟三層樓的轉角建築壓進一條 2.5:1 的橫帶，屋簷的挑出、招牌、亮著燈的門面全部
變成細節。詩也被連帶壓小：Ⓢ1（2026-08-10）那組字距 .131em、行高 1.75、
字級 11.5px，是被 291px 高的天空逼出來的，不是設計上想要的
（電腦版是 .32em／2.45／15px）。

二、拉高不會裁掉照片的上下（這一輪最關鍵的一件）

直式的框比照片瘦，object-fit: cover 的縮放倍率 s = max(W/1600, H/1058) 由
**高度**那一項決定（H >= 258 時都是），所以顯示高度恆等於框高 ——
**垂直方向永遠是整張照片**，天空在上、街面在下一列都沒少。拉高只往左右裁：

    照片高    看得到原圖寬        等效
    291px     1418px (88.6%)      改動前（右緣裁 13%）
    440px      938px (58.6%)      半屏
    570px      724px (45.2%)      三分二
    719px      574px (35.9%)      抵下緣（390x844）
    844px      489px (30.6%)      整屏

於是天空那個楔形整個放大，詩反而變寬鬆。逐像素量過（藍減紅 > 8 判天空，沿用
2026-08-10 的判準）三行詩到房子的餘裕，390x844：

    改動前＋Ⓢ1 的詩       +22 / +28 / +16 px
    抵下緣＋詩鬆兩階       +81 / +78 / +53 px

⚠ 這也是「定案為什麼可以不寫 object-position」的原因：基底那條 50% 100% 的
   垂直分量在直式框上不起作用，水平就是置中 ＝ 定案的「街景多」那一格。
   換成偏右的裁法就不能寫死百分比 —— 看得到的原圖寬會隨螢幕高度變。

三、順便修掉一件舊帳

「巷口」壓在對街車頭燈上（2026-08-10 為它加了 Ⓔ2 那塊暗斑，CLAUDE.md
第九節第 11 項）。新裁法把那盞燈整個裁掉：收尾句底下最亮的一列 L*97 -> L*40，
白字對比度 1.09 -> 6.50。Ⓔ2 那塊暗斑留著（不礙事，320 上還有 L*52／對比 4.21），
但它已經不是非有不可。

四、照片庫沒有第二張可以換

站上四張實拍：hero-clinic.jpg（日景，天空是亮的，白字讀不到）、
clinic-room-1/2.jpg（診間，整片白底，同上）、hero-clinic-night.jpg（現用）。
詩是白字、要壓在照片上，所以只有夜景這一張能當 HERO。
**這一輪動的是裁切與框，不是換照片。**

                份量  相合      清楚  的效率  相容

    半屏 52%     3.5   4.5       4.0   5.0     4.5    21.5
    三分二 67%   4.0   4.5       4.0   4.5     4.5    21.5

・現況在「找資訊」拿滿分是真的：第一屏一半是紙色區，主題與科別、搜尋框都已經
  露出來了。它輸在品牌份量與可讀性。
・整屏在「找資訊」只有 2.0：窄帶（地址、電話、1983／9／5）整條被推出第一屏，
  牙醫診所的網站不該讓人先捲一下才看到電話。
・整屏在「相合」也掉一階：只看得到 30.6% 的原圖寬，對街的房子與車全部裁掉，

・抵下緣在「風險」是 4.0：多了一條「照片高度看螢幕高度」的相依。

六、第二輪：詩還是和 logo 黏在一起

使用者看過第一輪：「你這樣設計很不錯欸。不過我發現詩可以再鬆一點或是再往下一點，
還是字可以再大一點，因為就算鬆兩階，看起來和 logo 還是有點近、黏在一起的感覺。」

量出來是**距離**差 2.2 倍，不是字太小。頁首下緣到詩第一行 ink 上緣的空隙，
除以詩自己的字高（用 Range 量 ink，不要量 span 的 rect —— 那個框含 line-height
的半行距，會多算幾 px）：

    版型                空隙     ÷字高   ÷照片高   詩÷診所名
    電腦 1280x800       80.0px   5.95    10.0%     0.792
    電腦 1440x900       90.0px   6.00    10.0%     0.884
    手機 改動前         11.7px   1.02     4.0%     0.774
    手機 提案第一版     38.6px   2.67     5.4%     0.972
    手機 定案           91.7px   5.93    12.8%     0.972

・**字其實已經偏大**：詩÷照片高，手機 2.15%、電腦 1.67%；詩÷診所名手機 0.97、
  電腦 0.88 —— 再放大就和 logo 一樣大，那正是 2026-08-09 朋友回報「兩塊字大小
  差不多、看起來 noisy」的成因。所以主力給位置，字級只從 11.5 加到 15.5px。
⚠ ÷字高 與 ÷照片高 兩個比值會指向不同答案（手機的字相對照片本來就大）。
   「黏在一起」是**字與字的關係**，所以以 ÷字高 = 6.0 為準。
・切換條因此從「鬆一階／鬆兩階」兩個套餐，拆成位置、字級、鬆緊三把尺
  ＋一把「上緣壓深」，各自可以單獨動。

七、⚠⚠ 這一輪推翻了一條沿用五天的約束

Ⓢ1（2026-08-10）把「詩不准碰到房子」當成硬約束，整組字距與位置都是照天空那個
楔形解出來的。**但那條約束真正的理由是對比度**，而它是在照片只有 291px、牆又小
又花的前提下訂的。照片拉到 719px、又是夜景之後，清水模牆自己就夠暗了。
逐行取 ink bbox 裡最亮的一格換算白字對比度（詩 15.5px、坐到第⑤階）：

    上緣壓深                 第一行   第二行   第三行   六個視窗最低
    不放（= 定案）            8.49     6.54     5.88     5.00
    開電腦版那層 46% .52/.30 10.54     7.97     6.85     5.53
    厚一階 58% .62/.40       12.05     9.46     8.23     6.74

**連「不放」都全部過 AA（4.5）。** 使用者三案看過，選了「不放」——
牆自己就夠暗，壓深只會讓天空變濁。
⚠ 所以 /history/hero-mobile-skyline.html 那張「能寫字的天空楔形」表
   **只適用於 74.72vw 那個版型**，不要再拿它來解字距。

九、窄帶接縫的起點色要重新量

正式站原本是 #151311 —— 那是**改動前那個裁法**下照片最後一列的中位數色
（2026-08-12 四輪定案的那條，CLAUDE.md 第九節第 16 項）。照片一拉高就換一批
像素，實測 L* 5.30 -> 7.28，起點色改成 **#181614**。不換的話那條線會回來
（上次是 +2.7 L*，這次會是 −1.3）。曲線一個字都沒改（S(t^1.6)、頭尾斜率 0、
整條攤到 100%），只是重算十一個色停：

    半屏                #171413（L* 6.70）
    三分二／抵下緣／整屏 #181614（L* 7.28）  <- 定案用這個

⚠ 量的是每一列的**中位數**，不是平均：照片下半部有路燈、車頭燈、門口的燈，
   幾顆亮點就能把整列的平均拉高 4 個 L*。

十、踩過兩次的坑：詩的參數要跟著「照片高度」，不是跟著寬度

第一版位置寫 21vw／25vw：390x844 上餘裕 +124/+60/+43，但 320x568 是
−9/−12/−24、360x640 −6/−6/−22。成因是**照片高度改由螢幕高度決定之後，天空的
楔形跟著螢幕高縮放，字卻還跟著寬度算** —— 短螢幕上字相對變大。
第二版把位置換成 svh：抵下緣過關，但半屏／三分二又壓到（L3 −4 ~ −19），
因為 svh 只對「照片高 = 一屏扣窄帶」那一格準。
第三版（定案）：位置與字級一律按 --ph（照片高度）等比例，再用 vw 與絕對上下限
夾住。七個視窗 × 五種高度全部成立。

⚠ 提案頁的 --ph 是 JS 現量寫進去的；**正式站改成純 CSS**
   `--ph: calc(100svh - 125px)`（窄帶實測 123~125px，取 125）。
   差 2px 只讓詩的位置差 0.4px、字級差 0.04px，但少一支 JS、少一個失效點。
   照片自己的高度是 flex 算的，所以就算窄帶哪天變高，版面不會錯位。
⚠ 下限 min(12px, 3.8vw) 的 min() 不能拿掉 —— 320 寬上 3.8vw = 12.16px，
   直接寫 12px 會讓最窄的螢幕反而字最大。

定案（2026-08-15 上線）

照片　抵下緣（.hero 改 flex 直向 ＋ height:100svh，.hero-photo flex:1）
      390x844 上照片 719px = 一屏的 85%，照片＋窄帶正好一屏
裁切　街景多（＝水平置中，把手機那條 object-position: left center 整條刪掉）
詩　　位置 .200×--ph、字級 clamp(min(12px,3.8vw), .0215×--ph, 15.5px)、
      字距 .32em、行高 2.45、全形空格不縮、首行後 .9em
      —— 後四項和電腦版逐字相同
窄帶　接縫起點 #151311 -> #181614，曲線不變
上緣壓深　不放（維持 .hero-photo::after { display: none }）
往下看的角形　不放（2026-08-13 在 cta-mobile 落選過，這一輪再問一次，仍然不放）

沒有動到的：電腦版（1280/1440/1920 逐項比對，照片高、詩的位置與字級 0 差異）、
iPad 直放 70svh、旋轉螢幕 62svh、Ⓔ2 那塊暗斑、hero-cue 的電腦版行為。
