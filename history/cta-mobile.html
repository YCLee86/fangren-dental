「標記高度」那一輪：31 / 34 / 38 / 41 / 44

第一版把標記直接撐到 44（WCAG 2.5.5 AAA），使用者：「為了增大點擊空間、
避免誤觸所以垂直幅度變大，但好像太大了，不然在現在這個版本跟原始版本的
中間做三個讓我比較看看。」→ 13px 平分四段取整，得 34／38／41。定案 34。

⚠ WCAG 2.5.8 的 AA 門檻是 24×24，44 是 2.5.5 的 AAA。34／38／41 三段
  都已經過 AA，過不了的只有 AAA。

反推內距（框 1px×2、行高 1.6）：
  .chips button        字 13.12 × 1.6 = 21.0  → 內距 = (h − 23) / 2
  .hours-filter button 字 12.80 × 1.6 = 20.5  → 內距 = (h − 22.5) / 2

  h            31(現況)  34     38     41     44
  chips          4.0     5.5    7.5    9.0   10.5
  hours          4.2*    5.75   7.75   9.25  10.75    * 原本 .2rem=3.2，量到 28.8

⚠⚠ 第二版改成用目標高回推，不再寫死 px：
      padding-block: calc((34px − 1.6em − 2px) / 2)
   因為使用者接著要求「字再大一點」，而字級一動，寫死的內距就會把塊高頂開
   （34 → 35.1 → 36.2）。1em 是按鈕自己當下的字級，所以兩把尺互不干擾。
   量過 5 種塊高 × 4 種字級共 20 組，塊高全部等於指定值。
⚠ 字級天花板是「內距不能是負的」：34px 的塊上限 (34−2)/1.6 = 20px；
  塊高若調回 31 就掉到 18.1px。高與字是一組的。

角形為什麼要掛在外層

⚠⚠ **mask-image 會作用在元素的偽元素上。**
第一版把角形寫成捲動容器自己的 ::before/::after，結果 Ⓐ 的遮罩把貼在邊緣的
角形一起淡掉 —— 量得到 opacity 是 .5，畫面上就是沒有。

解法是包一層 .swrap，角形掛在**沒有被遮罩的外層**上。
⚠ .swrap 平常是 display: contents，在版面上完全不存在。中立性驗過：
  五個寬度 × 六種設定，十一個元素的寬高座標 ＋ scrollWidth ＋ 文件高度，
  逐項完全相同。
⚠ 包完之後 .sbar 的 DOM 父層變成 .swrap，選擇器要從子代改成後代 ——
  display: contents 只影響版面，**選擇器仍然照 DOM 樹比對**。
⚠ 外層不要寫任何 overflow：一寫就擋掉裡面的黏著定位，而且子層的下外距
  不再穿透出來（門診表那排的 1.15rem 靠它）。

（角形還在捲動列裡的那一版另外踩過一個坑：負外距要扣的不只是自己的寬度，
  還要扣一份 gap —— gap 是每兩個 flex 項目之間都有一份，多兩個偽元素就多兩份，
  scrollWidth 769 → 784、第一顆標記被往右推 7.2px。搬到外層後自然消失。）

角形的垂直位置：對字面中線，不是盒子中線

量出來低 2.31px（375、字 13.12、塊高 34），**兩件事疊在一起**：
  ① 捲動列自己有 padding-bottom: .15rem（2.4px），
     包裝高 36.39 ≠ 按鈕高 34 → 幾何中心低 1.20px
  ② 中文的字面中線本來就在行框中線上方：
     按鈕盒中心 17.00、字面中線 15.89 → 又低 1.11px
1.20 + 1.11 = 2.31。只解其中一個都還會歪。

⚠⚠ **不能寫死成 em。** Blink 把行內盒的基線位置進位到整數 px，偏移量不是
  字級的線性函數，同一個字級在不同 DPR 上還會落在不同的整數
  （CLAUDE.md 第九節第 9 條記過同一個坑）。而且這裡又多兩個變數
  （塊高與字級兩把尺都會動它）。所以由 JS 現場量，寫進 --ar-y。
⚠ 量法：零尺寸 inline-block 探針取基線，canvas 的 actualBoundingBox 取字面框，
  **在 400px 上量再等比例縮**（Blink 回來的值以 1/64 em 為階）。
⚠ 這支不掛在 scroll 上：捲動不會改變垂直位置。

驗證：3 個寬度 × 2 種 DPR × 4 組（塊高／字級）× 兩排標記，差全部是 0.00px。

角形的透明度：跟餘量走，不跟手走

使用者：「滑動的時候不要變淡，是滑到底再隨著滑動減緩變淡。所以往右滑到底，
左角形並不會變淡也不會消失。這樣才符合介面設計的邏輯。」

⚠⚠ 舊模型（data-sc ＋ 700ms 計時器）有兩個錯，已整組拿掉：
  ・把「正在捲」當成要退場的訊號 —— 手在動不代表沒得滑了，
    結果一動手兩顆就一起變淡，在最需要提示的時候消失
  ・用 start／mid／end 三個離散狀態決定顯不顯示，到底那一瞬間是「啪」地消失

新模型：兩顆各看**自己那一側還剩多少可以滑**。
    左 = min(1, scrollLeft ÷ 48)      右 = min(1, (可捲總量 − scrollLeft) ÷ 48)

斜坡 48px：太短（~16）幾乎等於「啪」地消失，太長（~120）整趟有一大半時間
角形都是半透明的。主題那排可捲 434px，48 佔 11%。
過場 .15s linear 只是平滑捲動事件的顆粒，再長就會跟不上手指。

實測（基準 .7）：
  scrollLeft   0 → 左 0.000 右 0.700
              12 → 左 0.175 右 0.700
              24 → 左 0.350 右 0.700
              48 → 左 0.700 右 0.700   （之後一路維持，滑動中不變淡）
       離右底 24 → 左 0.700 右 0.350
       離右底 12 → 左 0.700 右 0.175
           到底 → 左 0.700 右 0.000   ← 使用者要的那一條

橫捲踩到的第一個坑：撐開的不是捲軸，是整張卡

⚠⚠ 門診表那排在 .info-card 裡，而那張卡是 .info 這個 grid 的項目 ——
**grid 項目的 min-width 預設是 auto**（不准比內容窄）。一排七顆不換行之後，
撐開的不是捲軸、是整張卡，整頁跟著長出水平捲軸（375 上量到溢出 296px）。
補一行 min-width: 0 才真的變成橫捲。
主題那排沒踩到，只是因為它的祖先是 flex 而它自己早就寫了 min-width: 0。

窄帶三行的間距：不能只加 gap

字抬一階之後行距沒跟著長，三行擠成一團。

⚠⚠ 2026-08-10 有一輪定案在管窄帶的上下平衡（當時使用者說「1983 那一列離窄帶
下緣還有距離，反而離地址電話很近」，兩邊各動 2px 收成 11.7／11.8）。

切換條本身學到的

・選擇器一律 html[data-x="on"] .foo（0,2,1），比原本的 .foo（0,1,0）高一階：
  「開」一定贏、「關」的時候整條不存在、原本那條自然接手。
  **不要用 !important**，那會讓關掉之後回不去原狀。
・需要新元素的項目，元素寫死在 HTML 裡、預設 display: none ——
  切換純粹是 CSS，不必在切換的當下動 DOM，關掉一定回得去。
