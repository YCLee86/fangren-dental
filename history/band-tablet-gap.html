這一頁是什麼（2026-08-10）
----------------------------------------------------------------------------
只為了看一件事：**視窗約 721–870px 時，窄帶第三格「5 個／部定專科」
和右邊的地址／電話疊在一起。**

這是既有的問題，不是 2026-08-10 改電話號碼造成的（改之前疊 19.7px、
之後 25.1px，兩張截圖比對過）。這一頁是三個修法的比較。

---- 為什麼會撞（實測，Chromium）----------------------------------------
三格整組的寬度**是固定的 531.5px**（內容寬 ＋ 每格左右各 4rem），
而且置中；地址電話那一組貼在版心右緣、寬 176.8px。
於是視窗每少 2px，三格的右緣只往左 1px，但聯絡組的左緣往左 2px ——
**空隙以每 2px 掉 1px 的速度收**，遲早歸零。

  視窗   第三格「部定專科」右緣   聯絡組左緣    空隙
   721            554.8            507.6      −47.2   撞
   760            574.3            545.4      −28.8   撞
   800            594.3            584.2      −10.0   撞
 ~821                                            0    臨界
   840            614.3            623.0       +8.8   擦邊
   870                                        ~+24    開始舒服
   880            634.3            661.8      +27.6   ok
  1159            773.8            932.5     +158.7   ok
  1160（換成一行版）                            +59.1   ok

所以壞掉的區間是 **721–870**，下限 721 是手機版的斷點（≤720 已經另有做法）。
⚠ 這兩個寬度是真的裝置：**iPhone 轉成橫的 844、iPad 直放 768**，都在區間內。

⚠ index.html 原本的註解寫「一行整組要 292.5px，兩行只要 172px、
   **一路都放得下**」—— 錯的就是這一句。兩行版自己確實放得下，
   但它沒有把「三格是固定寬度且置中」算進去。

---- 三案 -----------------------------------------------------------------
全部只在 @media (min-width: 721px) and (max-width: 870px) 裡生效，
這個區間以外一個像素都不動（電腦版、手機版都不受影響）。

  Ⓐ 三格收窄    三格的 padding-inline 從 4rem 隨寬度收到 1.7rem。
                窄帶高度不變（84px），聯絡組的位置與對齊完全不動。
                空隙在整段維持 22.9~26.5px —— 22.9 正好就是現況在 870 的值，
                所以和沒改的那一段接得起來，看不到跳動。
                ⚠ 代價：要在 721 撐開足夠空隙，4rem 得收到 **1.7rem**，
                   比 2026-08-07 那一輪**被淘汰的 1.9rem 還窄**。
                   等於在平板寬度把那個定案讓掉。

  Ⓑ 插成一列（兩行版）  聯絡組脫離絕對定位，變成 .shell 裡的一列，
                落在「瀏覽數」與「三格」之間（＝手機版的位置）。
                維持現在的兩行、靠左。**窄帶 84 → 106.4px（＋22.4）**。

  Ⓒ 插成一列（一行版）  同上，但改回一行、圖示與文字的間距回到 .45rem，
                整組置中。**窄帶 84 → 88.0px（＋4.0）** —— 一行剛好吃得下
                min-height 原本的餘裕，幾乎沒有代價。
                而且和 ≤720 的手機版**完全連續**：手機那一版本來就是
                「一行置中、夾在瀏覽數與三格之間」，等於把同一個做法往上長。

---- 量出來的結果（Chromium，實測）---------------------------------------
  案    721    760    800    840    870      窄帶高
  現況 −47.2  −28.8  −10.0   +8.8  +22.9      84.0
  Ⓐ    +26.5  +25.5  +24.6  +23.6  +22.9      84.0

⚠ Ⓐ 第一版用固定的 2.4rem，量出來 721 上只剩 4.0px。
   原因寫在下面 CSS 的註解裡：三格收窄時**第三格自己的右內距也跟著縮**，
   所以換到的空間只有直覺算式的一半。憑算式不量會漏掉這一項。

切換條在右下角，網址可帶 ?fix=now|a|b|c。**定案之後把切換條連同
data-fix 一起刪掉**，不要留到正式站。

---- 收尾句底下那塊暗塊加深（提案 Ⓔ2 定案，2026-08-10）--------------
使用者回報「巷口」剛好壓在車頭燈上看不清楚。逐字量過照片底下的亮度
（375 寬）：「巷」最亮 219、「口」最亮 236，白字 65% 疊上去的對比度只有
1.24 / 1.12（1.0 ＝ 完全看不見），其他十個字都在 3～7。

原本的 rgba(25,22,20,.72) 被 blur(18px) 攤開之後，在「巷口」的位置
（離暗塊左緣只有 24px）實際只剩約 0.44 不透明度，236 壓完還有 142。
所以把不透明度提到 .9、範圍放大，讓它在那一端還有密度。

⚠ **blur 一個值都不要動。** 一收就會看得出這是一個框 ——
   「看不出是框、只是路面自己暗下去」正是這塊東西的設計重點。
⚠ **只在手機。** 電腦版的裁切是下緣貼齊，收尾句落在純暗的路面上，
   十二個字最亮處都 ≤58、對比度 ≥5.9，不需要也不該加。

直立（旋轉）螢幕：照片不整屏（2026-08-09 定案）
--------------------------------------------------------------------------
使用者把 1920×1080 的螢幕轉成直的，回報「左邊的字看起來非常小」。
原因不是字級設錯，是**這一頁只有照片跟著高度長**：

                                  1440×900 → 1080×1920
.hero-photo  height: 100svh        900px → 1920px（2.13 倍）
.hero-poem   clamp(12.5px, 1.05vw, 15px)   15px → 12.5px（撞下限）
.hero-sign   clamp(11.5px,  .95vw, 14px)   14px → 11.5px（撞下限）
.hero-copy   padding-top …clamp(1.2rem, 4vh, 2.6rem)   41.6px → 41.6px（撞上限）

字級只讀 vw，還掉到 clamp 的下限；內距讀了 vh 卻撞在上限。高度多出來的
1000px 沒有任何一條式子接得住，全變成空天空 —— 三行詩在 900px 的畫面裡
佔 10.6%，在 1920px 裡只佔 4.1%。

而且照片的裁切整個換了方向：1600×1058（1.512）的橫幅塞進 1080×1920 的框，
cover 的縮放由高度決定（1920 ÷ 1058 = 1.815 倍），照片被放到 2904px 寬 ——
**左右各裁掉 31.5%，只露出中間 37%**，垂直方向反而一點都沒切。
所以電腦版定案的 `object-position: 50% 100%`（下緣貼齊）在這個比例下
完全沒有作用，要裁到垂直得矮到 37svh（1080 ÷ 1.512 = 714px）以下。

---- 定案：照片不整屏 -----------------------------------------------------
五案做成 preview/hero-portrait/ 給使用者在旋轉螢幕上比過（橫排放大、
直排靠上、直排置中、照片不整屏、以及不改的對照），他選了照片不整屏。

62svh 是「不整屏」的那個值：1920 高時照片 1190px，縮放降到 1.12 倍，
左右只裁掉 41%（原本 63%），街角、門面、隔壁的矮房子都回得來。
詩與收尾句因此靠近，不再是一撮小字隔著 1000px 空天空對望。
窄帶是 position: absolute; bottom: 0 掛在 .hero 上，會自己跟上來，不必處理。

字級仍要換成 svh —— 只把照片變矮不夠，字級讀 vw 這件事沒解決。
1.15svh 的錨點在電腦版身上（1440×900 的 15px 等於 1.667svh），保守一點取
1.15：1920 高時 22px。旋轉螢幕的觀看距離和一般螢幕一樣，字級要照桌機的
尺度看，不是照海報。下限 15px 是留給比較矮的直立畫面（例如 800×1200）。

---- 這一段的界線 ---------------------------------------------------------
min-width: 721px      721 是上面手機版型（max-width: 720px）的補集，
                      手機一個像素都碰不到。
max-aspect-ratio: 2/3 aspect-ratio 是寬 ÷ 高，所以這是「比 0.667 更瘦」。
                      1080×1920 = 0.5625 ✓、1200×1920（16:10 旋轉）= 0.625 ✓、
                      iPad 直放 1024×1366 = 0.75 ✗ —— 刻意排除，
                      它現在看到的是電腦版，那個樣子不動。

驗過：把這一頁與改動前放進同尺寸 iframe 逐項比對，1440×900 與 390×844
兩組的字級、行高、書寫方向、.hero-copy 內距、詩的座標、scrollWidth
**每一個值都相同** —— 電腦版與手機版真的沒被動到。

已知邊界：旋轉螢幕若開 150% 縮放，視窗只有 720 CSS px 寬，
會落回手機版型而不是這一段（720 是 max-width: 720px 的邊界，含）。
那個結果也還可以看，所以不另外處理。

---- Ⓐ 三格收窄 ----
⚠ 第一版用固定的 2.4rem，量出來 721 上只剩 4.0px，等於還是貼著。
   原因：三格整組窄了 6×Δ、置中所以右緣往左 3×Δ，**但第三格自己的右內距
   也縮了 Δ**，所以「部定專科」那幾個字的右緣只往左 2×Δ —— 換到的空間是
   我一開始以為的一半。實測 Δ=25.6px 時 gain=51.2（不是 76.8）。

改成隨寬度連續變化，避免在 870 那一刀出現看得見的跳動：
  870 上 = 4rem（和外面完全接得起來）
  721 上 = 1.7rem（空隙 +26.4px）
線性內插 → clamp(1.7rem, 24.7vw - 150.9px, 4rem)。

⚠ **這一案的代價就寫在這裡**：要在 721 撐開足夠的空隙，
   4rem 必須收到 1.7rem —— 比 2026-08-07 那一輪**被淘汰的 1.9rem 還窄**。
   換句話說 Ⓐ 等於在平板寬度把那個定案讓掉。
---- Ⓑ 插成一列，維持兩行靠左 ----
position: static 之後它就是 .band .shell 這個直向 flex 的第二個項目
（標記順序是 瀏覽數 → 聯絡 → 三格），也就是手機版的位置。
.shell 已經 align-items: center，所以整塊會置中、塊內兩行仍靠左。
⚠ 這條**不能放右下角**：窄帶就壓在整屏照片的下緣，切換條擺右下會正好蓋住
要比較的那一塊（第三格與地址電話）。2026-08-10 在 iPad 上實測撞到，改到上方置中 ——
那裡是照片的天空，整段是空的。top 用 96px 讓開固定頁首。
主題與科別的篩選。與手機版同一支，一行都沒有改：
1. 按一下同時篩文章與醫師；再按同一顆＝取消。
2. 沒有 JS 的時候 chips 就是按不動的按鈕，底下什麼都不會被藏 —— 不會壞。
3. 對應關係讀的是 HTML 上的 data-spec，跟配色共用同一個屬性，
 所以顏色與篩選永遠不可能對不起來。
