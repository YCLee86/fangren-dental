〔CLAUDE.md〕
8. **CSS 註解裡不能出現 `</style>` 那個字串**（2026-08-11，`preview/doc-cross-spec/` 踩過）。
   HTML 解析器找結束標籤是**純字串比對**，不管它在不在 CSS 註解裡 —— 寫下去樣式表就在
   那一行被切斷，後面整段全部失效。**症狀最惡劣的地方是它不報錯**：畫面照常、
   舊樣式都在，只有新加的那一段「沒吃到」，很容易往選擇器權重或快取的方向找一小時。
   `<script>` 裡的 `</script>` 同一條。這一站的註解寫得很長，特別容易踩。
   要在註解裡指這件事，就用文字描述（「這份樣式表結尾」），不要貼標籤本身。

============================================================================
這一頁是什麼（2026-08-11・提案中，尚未套進正式站）
----------------------------------------------------------------------------
⚠ 先分清楚兩件事：

① **李柄輝醫師專長欄的「牙周照護」已經上線了**（2026-08-11）。那只是一行文字，
   不在這一頁的討論範圍。
② **這一頁在問的是篩選**：主題與科別按下「牙周治療」的時候，要不要**連他的
   醫師卡一起顯示出來**。這一件還沒定案，正式站的 index.html 一個字都沒動。

── 起因（使用者，2026-08-11）────────────────────────────────────────────
「還是一般牙科的標籤就好，但主題與科別點到牙周治療，可以也把他的醫師介紹
  卡片顯示出來。」

── 為什麼原本做不到 ─────────────────────────────────────────────────────
正式站的篩選只讀一個屬性：

    var hit = (!spec || rec.el.getAttribute('data-spec') === spec) && …

而 data-spec **同時是配色的來源**（[data-spec="general"] 那一排 CSS 變數）。
index.html 那段註解原本寫著這是刻意的：「跟配色共用同一個屬性，所以顏色與
篩選永遠不可能對不起來」。所以「出現在牙周那一科、但維持一般牙科的綠」在現在
的結構下是矛盾的 —— 把 data-spec 改成 perio，卡片會跟著變青綠（使用者明講不要）。

── 這一頁的做法 ─────────────────────────────────────────────────────────
**把「配色的科別」和「篩得到的科別」拆成兩個屬性**：

    <article class="doc" data-spec="general" data-spec-also="perio">
                         └ 顏色／藥丸，只有一個   └ 篩選另外吃得到，空白分隔

data-spec 的意義一個字都沒變，所以顏色與藥丸不會有任何變化；data-spec-also 是
新的，**只有篩選那一支 JS 會讀**。搜尋框不受影響（它本來就讀整張卡的
textContent，打「牙周」早就找得到他）。

⚠ **這等於放棄了「顏色 ＝ 篩選」那個不變量**，是這次改動真正的代價。
  換來的是「一位醫師可以出現在兩科底下」。日後看到一張卡出現在和它顏色不同的
  科別底下，成因就是這個屬性，不是 bug。

── 切換條（右下角，網址可帶參數）───────────────────────────────────────
?doc=a|b|c  Ⓐ 現況（點牙周治療只有李侑津）
            Ⓑ 顯示，什麼都不加　　← 使用者要的，**預設**
            Ⓒ 顯示，並在專長那一欄把命中的那幾個字用細線標起來
?n=1|2      Ⓝ1 只做李柄輝一位　　← 使用者要的，**預設**
            Ⓝ2 把其他明顯的跨科也一起補上（見下）

── Ⓒ 是我加的，不是使用者要求的 ─────────────────────────────────────────
問題很具體：Ⓑ 之下按「牙周治療」會出現一張**綠色**的卡，旁邊李侑津那張是青綠
的，看的人不知道它為什麼在這裡。Ⓒ 只在「正在篩的那一科」對得上的那幾個字底下
畫一條 1.5px 的線，顏色用那一科的字階（牙周 #2a6d69）。
⚠ 這是全站唯一一處讓兩個科別色出現在同一張卡上，只有一條髮絲線的量。
  不喜歡就選 Ⓑ，機制完全一樣，差別只有那條線。
⚠ 線是 text-decoration 畫的，不是 border —— 不佔位、不會把 dd 撐開，
  而且會自己閃過中文的下伸部。（Blink 會把 border-width 進位到整數 px，
  髮絲線一律不要用 border，見 CLAUDE.md 第八節 nav-scrollspy 那一條。）

── Ⓝ2：如果同一條規則套到全部九位 ──────────────────────────────────────
這是**這次改動最需要先想清楚的一件事**：李柄輝出現在牙周底下之後，底下這幾位
為什麼沒有跟著出現？他們的專長欄白紙黑字寫著：

  李侑津　(perio)　「植牙手術、固定假牙、活動假牙」→ 植牙・假牙重建
  謝耀慶　(kids) 　「一般牙科治療」　　　　　　　　→ 一般牙科・定期檢查
  謝耀慶　(kids) 　「兒童隱適美、兒童早期矯正」　　→ 齒顎矯正（可議）
  林晏妤　(kids) 　「兒童隱適美、兒童早期矯正」　　→ 齒顎矯正（可議）

Ⓝ2 就是把這四筆一起打開的樣子。切過去看一次再決定：只做一位是「特例」，
全部做是「規則」，兩個都可以，但要是有意識選的。
（矯正那兩筆標「可議」：兒童早期矯正和齒顎矯正專科不是同一件事，兩位矯正專科
  醫師做的是後者。要不要算是使用者的判斷，不是我該替他決定的。）

── 落選 / 沒做的 ────────────────────────────────────────────────────────
・**把李柄輝的 data-spec 改成 perio**：卡片會變青綠，使用者明確說要維持一般
  牙科的標籤。連提都不用提。
・**在文章卡上也掛 data-spec-also**：目前六篇文章一篇都不需要跨科。機制寫成
  通用的（cardIdx 和 docIdx 走同一個 specHit），但沒有掛任何屬性上去。
・**讓 .filter-note 寫「2 位醫師（1 位跨科）」**：它已經會寫「牙周治療：
  1 篇文章、2 位醫師」，再拆一層字太多。

── 這一頁和正式站的差異（全部）─────────────────────────────────────────

     srcset、去要 /preview/<name>/assets/… 而 404，**畫面上不會出現破圖，
     只會安靜地變成 alt 文字疊在黑底上**，很容易當成「照片比較暗」。
     （nav-frame-height 踩過。）
3. 計數器那支 script 拿掉，數字寫死示範值 —— 不然每開一次提案頁就會對

4. 醫師卡多了 data-spec-also / data-spec-also2 與 <span class="hit">。
5. 篩選 JS 的 pass() 前面多一支 specHit()。

直立（旋轉）螢幕：照片不整屏（2026-08-09 定案）
--------------------------------------------------------------------------
使用者把 1920×1080 的螢幕轉成直的，回報「左邊的字看起來非常小」。
原因不是字級設錯，是**這一頁只有照片跟著高度長**：

                                  1440×900 → 1080×1920
.hero-photo  height: 100svh        900px → 1920px（2.13 倍）
.hero-poem   clamp(12.5px, 1.05vw, 15px)   15px → 12.5px（撞下限）
.hero-sign   clamp(11.5px,  .95vw, 14px)   14px → 11.5px（撞下限）
.hero-copy   padding-top …clamp(1.2rem, 4vh, 2.6rem)   41.6px → 41.6px（撞上限）

字級只讀 vw，還掉到 clamp 的下限；內距讀了 vh 卻撞在上限。高度多出來的
1000px 沒有任何一條式子接得住，全變成空天空 —— 三行詩在 900px 的畫面裡
佔 10.6%，在 1920px 裡只佔 4.1%。

而且照片的裁切整個換了方向：1600×1058（1.512）的橫幅塞進 1080×1920 的框，
cover 的縮放由高度決定（1920 ÷ 1058 = 1.815 倍），照片被放到 2904px 寬 ——
**左右各裁掉 31.5%，只露出中間 37%**，垂直方向反而一點都沒切。
所以電腦版定案的 `object-position: 50% 100%`（下緣貼齊）在這個比例下
完全沒有作用，要裁到垂直得矮到 37svh（1080 ÷ 1.512 = 714px）以下。

---- 定案：照片不整屏 -----------------------------------------------------
五案做成 preview/hero-portrait/ 給使用者在旋轉螢幕上比過（橫排放大、
直排靠上、直排置中、照片不整屏、以及不改的對照），他選了照片不整屏。

62svh 是「不整屏」的那個值：1920 高時照片 1190px，縮放降到 1.12 倍，
左右只裁掉 41%（原本 63%），街角、門面、隔壁的矮房子都回得來。
詩與收尾句因此靠近，不再是一撮小字隔著 1000px 空天空對望。
窄帶是 position: absolute; bottom: 0 掛在 .hero 上，會自己跟上來，不必處理。

字級仍要換成 svh —— 只把照片變矮不夠，字級讀 vw 這件事沒解決。
1.15svh 的錨點在電腦版身上（1440×900 的 15px 等於 1.667svh），保守一點取
1.15：1920 高時 22px。旋轉螢幕的觀看距離和一般螢幕一樣，字級要照桌機的
尺度看，不是照海報。下限 15px 是留給比較矮的直立畫面（例如 800×1200）。

---- 這一段的界線 ---------------------------------------------------------
min-width: 721px      721 是上面手機版型（max-width: 720px）的補集，
                      手機一個像素都碰不到。
max-aspect-ratio: 2/3 aspect-ratio 是寬 ÷ 高，所以這是「比 0.667 更瘦」。
                      1080×1920 = 0.5625 ✓、1200×1920（16:10 旋轉）= 0.625 ✓、
                      iPad 直放 1024×1366 = 0.75 ✗ —— 刻意排除，
                      它現在看到的是電腦版，那個樣子不動。

驗過：把這一頁與改動前放進同尺寸 iframe 逐項比對，1440×900 與 390×844
兩組的字級、行高、書寫方向、.hero-copy 內距、詩的座標、scrollWidth
**每一個值都相同** —— 電腦版與手機版真的沒被動到。

已知邊界：旋轉螢幕若開 150% 縮放，視窗只有 720 CSS px 寬，
會落回手機版型而不是這一段（720 是 max-width: 720px 的邊界，含）。
那個結果也還可以看，所以不另外處理。
