三、iPad 特有的三個坑

① **兩段各有一個寫死的 126px**（＝當初量出來的窄帶高度），要跟著倍率長：
     A 段　`--ph: calc(100svh - 126px)`　　→ 乘上倍率
           --ph 是「照片高度」，詩的字級與位置都按它等比例算；不乘的話
           詩的比例會算錯。
     B 段　`--band-h: 126px`　　　　　　　 → 乘上倍率
           收尾句讓開的量是 `calc(var(--band-h) + clamp(1rem,3vh,2rem))`，
           不乘的話收尾句會被窄帶蓋住。
   實測窄帶 126.6 → 150.4px，估值與實際差 0.4px，可以接受。

② **「往下滑」那顆指標**：大小（44×39.5）與兩條角形**不放大** —— 那是觸控
   下限與圖形，不是字。但它的垂直位置是「距窄帶下緣 34.9px」＝ 對齊
   「5個／部定專科」那一列的中線，而窄帶裡全是 rem，字一放大那一列就往上移。
   所以 34.9 要跟著長：`bottom: calc(34.9px * 倍率 - 39.5px / 2)`。
   四個尺寸 × 五段實測，對齊偏差都在 ±0.3px 以內。

③ **窄帶長高會吃掉照片**（A 段照片是 flex 吃剩下的高度）：
   834×1112 上照片 985.4 → 961.6px（一屏的 88.6% → 86.5%），
   「照片＋窄帶正好一屏」維持 ±0.0px。這是 flex 的正常行為，不是破圖。

五、量測面板學到的一件（下次一定會再踩）

**把版面暫時切到「現況」量一次再切回來的時候，一定要先把 transition 關掉。**

頁首的高（`.site-head .shell`）與標誌的 flex-basis 都掛著 .2s 的過場，
切過去的那一瞬間 getBoundingClientRect 讀到的還是**舊值** —— 量出來的
「現況」會等於「放大後」。踩到的症狀：iPad 這一頁的「頁首 → 詩」現況量成
8.08%（正確是 10.00%），因為頁首高在三個狀態下都讀到同一個數字。

    var st = document.createElement('style');
    st.textContent = '*, *::before, *::after { transition: none !important; animation: none !important; }';
    document.head.appendChild(st);
    ...切狀態、量、切回來...
    st.remove();

⚠ 同一件事也會騙過「調整視窗大小之後直接量」：那時過場也在跑。
  用瀏覽器工具驗證跨斷點的改動時，**改完視窗要重新載入再量**。
