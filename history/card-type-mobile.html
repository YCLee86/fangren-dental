踩到的坑

① `overflow: hidden` 切的是**內距框**，所以卡片的框線永遠在照片外面一圈，
   照片一定比卡窄 2px。要讓照片蓋過框線不能用負 margin（會被切掉），
   也不能改成 `overflow: visible`（圓角裁切會沒了、照片上面兩角會方出來）。
   改成 border: 0 ＋ inset box-shadow —— inset 陰影畫在自己的背景之上、
   子元素之下，所以照片那幾列被  蓋住、卡身那幾列照舊看得到。

② 門診表是 `table-layout: fixed`、左欄寫死，而 `tbody th` 是 `white-space: nowrap`
   —— 字一大就會**橫著蓋到第一格的點上**（表格不會撐破卡，所以沒有水平捲動，
   症狀是重疊）。左欄的寬度要跟著字級重算，而且要留餘裕：那是拿 Noto Sans TC
   量的，iOS 上是 PingFang，數字寬度不會一模一樣。

③ 「間隔縮短」這條路**報酬遞減**：間隔 ＝（左欄 − 時間字寬）＋（日子欄 − 點）÷2。
   左欄每收 8px，日子欄就跟著變寬，而點是置中的 —— 實際只少 7px。
   再往下就要改成「點靠左」，那是版面決定不是微調。

④⚠⚠ **牌子的幾何有一半寫死在絕對單位上**，字級一放大就全部不成比例。
   使用者第七輪回報的四件其實是同一個成因：
     底線離字面　2.2（在 16px 上調的 ＝ .1375em）→ 22.4px 還用 2.2 就掉到 .098em
     兩行的距離　markup 寫死 23 → 沒跟著長，底線和下一行擠在一起
     盒子貼不到尖端　牌子的大小是量內容算的、尖端是釘死的，
       壹車房那塊在 ×1.4 時盒子右緣 338.4 已經**越過**尖端 332，
       尾巴變成反向的缺口 —— 那就是「形狀很怪」
   三處都改成跟著字級走（比例、比例、由 JS 沿尾巴方向平移把盒子貼回尖端）。

⑤⚠⚠ **`preserveAspectRatio="slice"` 是 markup 屬性，電腦版也吃得到。**
   盒子高 531.43 是小數，slice 會因為浮點誤差多縮放千分之一，
   逐像素比對量到整張地圖約 0.35% 的邊緣像素有差（最大 47 階）。
   裁切改成用外層 `.map-win` 當視窗（電腦版 `display: contents`，不產生盒子），
   SVG 畫 130.2326% 再往左推 17.558%。

⑥ `translate(0 0)` 也會讓那一段重新光柵化 —— 位移是 0 就**不要留 transform**。

⑦ 診所名牌的字是 15px、停車場那三塊是 16px，所以同一個絕對值 2.2 換算成比例
   是 .14667em 與 .1375em —— **兩個不一樣**。統一寫 .1375 的話電腦版那條底線
   會往上跑 0.14 個單位，逐像素比對抓得到（486 個子像素、最大 17 階）。

「電腦版和 iPad 都不動」是怎麼驗的

fullPage 截圖、DPR 1，對 origin/main 逐像素相減：

  1440×900　　　　　0 / 23410080 個子像素有差
  1280×800　　　　　0 / 20252160
  1024×768　　　　　0 / 19433472
  834×1194（iPad 直放）0 / 15417324
  721×1000　　　　　落在截圖雜訊裡

⚠ 721 那一格不是零，但**同一份程式碼跑兩次的差是 974875**，
  而新舊比對只有 608860 —— 雜訊來源是 HERO 那顆會浮動的指標與窄帶的數字動畫。
  驗這種事一定要先跑一次「同一份程式碼、兩次截圖」當基準，否則會追著鬼跑。
