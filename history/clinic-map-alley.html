clinic-map-alley — 簡易地圖補一條沒畫到的小巷

提案期的產生器 tools/map-alley-preview.mjs（定案時刪掉，同一個 sha 還原得到）
成品：index.html 的簡易地圖，文化路北邊那一排街廓（只動兩個 rect）

起因

使用者拿站上的地圖與 Google 地圖並排：「我發現網站的簡易地圖少畫了一條路。 文化路上平和街口跟元大銀行中間有一條小巷。」

位置是量出來的，不是抓的

從使用者那張 Google 地圖截圖（1125 寬的原圖）逐像素掃road 的色帶： 

平和街　中心 x 169（色帶 130~208）
永樂街　中心 x 890（色帶 856~936，北邊 845~925）
那條小巷　中心 x 491（色帶在 y500 是 453~508、y700 是 460~514，微微向右斜）
文化路　　y 742~913

→ 小巷落在平和街與永樂街之間的 (491 − 169) / (890 − 169) ＝ 44.7%

地圖的 viewBox 裡平和街中心 109、永樂街中心 339， 所以 109 + 0.4466 × 230 ＝ 211.7 → 中心 x 212（提案頁的面板現場量到 44.8%）。

它只往北通到文化路，不往南（x=482 那一條在文化路以南沒有任何縱向色帶）， 所以在這張圖上它是文化路上面那一排街廓裡的一小段缺口， 和平和街、永樂街、永安路在最上緣露出來的那一截一樣高（21 個單位，390 寬的手機上約 15.7px）。

寬度：一把四格的尺，使用者選 12

現況　沒有這條巷子
Ⓐ 12　＝ 站上那兩條沒有名字的巷子（19 巷北邊那條平行巷、平和街 33 巷）　← 定案
Ⓑ 17　＝ 平和街 19 巷、永安路 14 巷（有名字的那兩條）
Ⓒ 21　＝ 照實際比例換算（它在 Google 上約是永樂街的 70%）

三格的寬度比一條街（30）＝ 40% / 57% / 70%。使用者選 Ⓐ 12。 那條巷子在 Google 上沒有名字，所以圖上沒有標字。

⚠⚠ 第二輪：平和街到文化路就到底，沒有穿過去

使用者看過第一版之後補的：「而且平和街到文化路就到底了　沒有穿過去。」 他是對的，而且資料本來就在第一輪自己量的那張表裡 —— x=174（平和街）那一條掃出來只有文化路那一段橫帶（y 742~913），北邊一個像素都沒有， 我量到了卻沒有去讀它。

通則：為了 A 去量出來的東西，往往同時回答了 B —— 量完要把整張表唸過一次， 不要只讀自己當下在找的那一格。

定案的做法（只動兩個 rect）

文化路北邊那一排（y -20 ~ 21）：

　平和街以西　 x -20　width 114　→　x -20　width 226　（-20 ~ 206，橫跨平和街）
　平和街～永樂街 x 124　width 200　→　x 218　width 106　（218 ~ 324）

　中間 206 ~ 218 就是那條小巷（寬 12、中心 212）。

街廓與街道的座標一個單位都沒動 —— 那張圖排了四十二輪，這一輪只改這兩塊的 x 與 width，rx=4 的圓角、其餘四排、所有街名、三塊停車場、圖釘與路線全部原封不動。 其他三排仍然留著平和街的缺口（它從文化路往南是真的存在）。

沒有動的一件

永安路北邊那一截。它落在那張截圖的右邊界外（換算過去約在 x 1304，而圖只有 1125 寬）， 看不到它有沒有穿過文化路，沒有證據就不改。日後確認了再一起處理。 永樂街那一截是對的（截圖上 x 845~925 在文化路以北量得到）。

提案頁本身

tools/map-alley-preview.mjs，index.html 的快照（照 CLAUDE.md 第八節那四件做： 相對路徑往上兩層、計數器整支拿掉並驗過、noindex、切換條插在最後一個 body 結束標籤前面）。 切換條只有一排四格，面板現場量：小巷在圖上多寬、往北那一截多長、中心 x 換算成 「平和街到永樂街之間的百分之幾」、寬度比一條街多少、比例尺、水平捲動。

⚠ 「對照現況」那一格要逐格等於站上 —— 第二輪多了「平和街封起來」之後， 現況那一格仍然是平和街穿過去、也沒有小巷，不然比不出差別。

⚠ 螢幕上多大拿 SVG 自己的 getScreenCTM() 算，不要自己推 preserveAspectRatio: slice 的比例尺（手機上那張圖是裁掉左右的）。
