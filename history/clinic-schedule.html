這一頁在做什麼

使用者拍了診所門口那面磁鐵門診表（白板 ＋ 七色磁鐵 ＋ 右側圖例），
說「目前的門診表長這樣，列入網站門診表的參考」。

在此之前，首頁 #clinic 的「看診時間」卡只有四行字：
  週一至週五 / 上午 08:45–11:30 / 下午 13:45–16:30 / 晚上 17:45–20:00
板子上有的「哪一科在哪一節」，網站上完全看不出來。

這一頁做了四種版型讓使用者挑，定案 Ⓓ 並在 2026-08-13 換掉那張卡。

板子和當時網站對不起來的三件

1. 時段。板子是 12:00 / 16:40 / 20:30，網站寫 11:30 / 16:30 / 20:00。
   **板子這一組和 LINE 官方帳號上的那一組完全相同** —— CLAUDE.md 第十節
   記著的三邊不一致，板子這一票投給了 LINE，網站原本是唯一的少數。
   定案上線時已改成板子這一組。

2. 週六。板子上週六早診有兩顆磁鐵（一般牙科＋齒顎矯正），網站寫「週六、週日休診」。
   ⚠ **這一件到定案上線為止都沒有確認過。** 使用者中途指示「六日拿掉」，
   所以表格只排週一到週五，網站維持「週六、週日休診」。
   板子上那兩顆磁鐵因此沒有出現在網站上。日後若確認週六早上有診，
   要補回週六那一欄（只有早診那一格有點），並改 .info-note 那一句
   —— JSON-LD 會自己跟上（tools/schema.mjs 讀 thead 的 th scope="col"）。

3. 顆粒度。板子是「哪一科在哪一節」，網站只有一段總營業時間。這正是這一輪要解的。

顏色：用站上的科別色，不是板子的磁鐵色

板子的七色和站上的七色只有兒牙、矯正大致對得上，其餘五科完全不同
（板子的一般牙科是棕、牙周是桃紅、根管是紫、假牙是橘紅、外科是綠；
站上分別是綠、青綠、磚紅、藍、紫）。

PALETTE.md 是配色的唯一依據，所以整輪一律用站上的 [data-spec] 那組值，
**沒有從照片取任何一個色**。「要不要反過來讓實體板子的磁鐵跟網站一致」
是另一個問題（換磁鐵成本很低），沒有做。

搬進正式站的時候還多做一件：提案頁上的四個灰（#9aa09b／#ccd0cd／
#dee2e3／#8b908a）是隨手挑的，**一顆都沒有帶進 index.html** ——
格線與被篩掉的點改用 --rule、字與有診的點改用 --ink-soft。

四種版型與三輪修正

第一輪做了三案：
  Ⓐ 一週一張表（和板子同樣的排法，手機上格子裡只留色點）
  Ⓑ 依星期（一天一張卡）
  Ⓒ 依科別（一科一列，想找「矯正什麼時候看」最快）

使用者接著給了兩個同業站當參考（drsunkist.com、drcmliu.com），
兩站的骨架都和板子一樣：日子當欄、早午晚當列、格子裡只放點。
三件從那兩站抄回來：
  ・時段寫在列標題上，不另外開一欄
  ・不符合的點是「淡掉」不是「拿掉」—— 格子的節奏不破
  ・今天那一欄墊底色；休診寫在圖例那一行，不在格子裡放「休」
drcmliu 上面那排分頁是切「哪一間診所」，我們只有一間，換成切**科別**。
→ 這就是 Ⓓ 點陣表，並設為預設。

Ⓓ 之後被使用者修了三輪：

Ⓓ 第二版 —— 「點太多，每個門診一個點就好，選到的科別再套色，版面也不夠簡約精緻」
  ・一格一顆點 ＝ 這一節有診（原本是一科一顆，最多四顆）。點數 36 → 16。
  ・因此**沒有圖例**了，上面那排切換就是圖例。
  ・欄的分隔線拿掉、外框與格線只留橫的細線、列高放到 1rem。
  ・順帶解掉一件：矯正與贋復是全站最近的一對藍（ΔE 13.3），
    一格一顆點之後**一次只有一科有顏色**，兩顆藍不會同時出現在同一張表上。

Ⓓ 第三版 —— 「底色為今日拿掉，六日拿掉，科別選到的時候字變色＋底線不清楚，
             改成像科別標籤，點到的時候整個標籤套色」
  ・篩選改成和首頁「主題與科別」完全同一組值（.chips button）。
    純文字加底線那一版整組刪掉 —— 站上本來就有做同一件事的元件。
  ・今日底色與「底色為今日」那一行整組移除。
  ・表格只排週一到週五。

Ⓓ 第四版 —— 「表的下方有文字『顯微根管　週三早　週三午』，這個也拿掉」
  ・選到科別之後那一行文字摘要移除（表格自己已經說了同一件事）。
  ・國定假日那句前面的米字號拿掉（index.html 本來就沒有記號）。

文案：第一顆標記叫什麼

使用者：「那個全部好像怪怪的，感覺應該是要留著，但全部這個詞有點直白。」

定案 **開診時段**（使用者選的）。表上那些點就是開診時段，是這一排裡最具體的一個，
也是診所自己會講的話。

落選：
  ・一週門診 —— 把軸拉到時間而不是科別，弱一階（曾短暫上線一版）
  ・門診總覽／總覽 —— 「總覽」在印刷品上也常見，不算 UI 詞彙；
    放在七個具體科別中間，抽象的兩字詞反而一眼就知道它不是科別。仍然落選。
  ・各科門診 —— 「各科」和「一般牙科」擺一起有點黏
  ・全部門診 —— 還是「全部」
  ⚠ **不分科別 —— 不要用。** 它會緊挨著「一般牙科」站著，而醫院裡「不分科」
    本身就是一個科別的講法，兩顆並排會被讀成又一個科。

⚠ 首頁「主題與科別」那排 chips 的第一顆**仍然是「全部」**，這一輪刻意沒有動它
  —— 那一排篩的是文章與醫師、不是時段。兩者不同是刻意的，不要順手統一。

文案：表格底下那一句

使用者提出的問題：兒牙、口外這類特別門診的醫師**不是每週都到**（隔週或不固定），
但他明確不要在表上標「哪幾顆是隔週」、也不要列日期或當月排班 —— 那樣太複雜。
連固定班的醫師也偶爾會不在。所以想在底下加一句總括的但書。

我先寫的是：
  「部分特別門診不是每週都有。實際看診時段與國定假日安排，請來電確認並預約。」
使用者改成（**定案，逐字，不要再潤飾**）：
  「國定假日與各科特別門診請來電確認。」
短了一半，而且把「預約」拿掉了。

⚠ 只寫「來電」是因為站上看得到的聯絡方式只有電話 —— LINE 只出現在 JSON-LD 的
  sameAs 裡，頁面上沒有連結，也沒有任何線上預約。不要寫出站上不存在的動作。
  （那兩個參考站都有「加 LINE 預約」的浮動按鈕，我們沒有。）

搬進正式站時做的四件

1. **表格寫成靜態 HTML。** 提案頁是 JS 產生的，正式站不行 ——
   理由和 CLAUDE.md 第一條（首頁文章列表不准改成 JS 產生）完全相同：
   看診時間是這一站最關鍵的一項事實，爬蟲與沒有 JS 的瀏覽器都必須看得到。
   JS 只做「點某一科就套色」，關掉 JS 之後整張表仍然完整，只是點不動。

2. **.info 從三欄改成「上面兩張、下面一整條」。** 表格＋八顆標記塞不進三欄的
   347px（標記會排成四行，整張卡比地址、電話高三倍），而 grid 會把同一列的卡
   一起拉到最高那張的高度，結果是左邊兩張幾乎全白。
   表格本身仍然收在 620px。

3. **tools/schema.mjs 的 parseHours 跟著改。**
   ⚠ 原本讀 <p><b>週一至週五</b>，換成表格之後第一個 <b> 變成「早」，
     照舊寫法會解不出來、**整段營業時間會從 JSON-LD 消失而且不報錯**。
   現在開診日讀 thead 的 <th scope="col">（一二三四五），
   時段與休診日的讀法沒變（時間範圍的正規式、「週六、週日休診」）。
   ⚠ 這個讀法的前提是**列出來的每一天都三節全開**。日後若出現
     「某一天只有早診」，要改成逐格判斷，不能再假設整欄一致。
   ⚠ 也**不要把那個 div 的 class 從 "info-card" 改掉** ——
     parseHours 的正規式比對的是 class="info-card" 這個完整字串。

4. **顏色只用既有變數**（見上面「顏色」那一節）。
