一、名牌變成連結

「芳仁牙醫診所」那塊實心綠底白字的名牌（2026-08-14 第三十輪加的），
現在和停車場那三塊淺底藍字的牌子結構完全一樣：

    <a class="rl-link" href="…">
      <g class="rl-pin">…實心水滴…</g>
      <text class="cl-nm">芳仁牙醫診所</text>
      <line class="rl-ul"/>
    </a>

・class 沿用停車場那三塊的 rl-link／rl-pin／rl-ul，所以圖釘的擺位、底線的
  算法（對字面下緣 +2.2）、以及「連結要 stopPropagation」那一條全部自動繼承。
  ⚠ stopPropagation 非有不可：地圖底層有一個「點空白處＝收回」的 handler，
    不擋的話點名字會先把牌子關掉，連結還沒開就沒了。
・顏色在 CSS 多寫一階換掉（.map-svg .clab .rl-pin / .rl-ul）：
  停車場那三塊是路牌藍 #365685，診所這塊的底是實心綠，所以圖釘與底線都要
  紙卡色 --card。⚠ 不要寫 #fff —— 同一塊綠上那顆牙齒標誌用的就是 --card，
  一塊綠上只准一個白。
・JS 的第 (1) 步選擇器要從 .rl-nm 改成 .rl-nm, .cl-nm —— 診所那塊的文字
  class 一直叫 cl-nm（字級 15 與字距 .04em 都和停車場那三塊不同，本來就沒共用）。
  漏掉的話那顆圖釘會留在原點 (0,0)。

連結指到 clinic.json 的 sameAs[0]：
    https://maps.app.goo.gl/bKSrVyS2Qu2xvnMj7
⚠ 那是 2026-08-10 使用者本人分享出來的短網址，和停車場那三條同一種來源。
  不要換成 clinic.json 的 hasMap（?api=1&query=… 的搜尋網址）——
  那條是給機器的後備。

二、第一次回報：相對距離

量出來是真的。成因是圖釘的高 17 與間距 3 原本是**寫死的絕對值**，
而兩種牌子的字級不一樣（停車場 16px、診所 15px，.clab text 自己一條）：

                字級   釘高        間距
    停車場 ×3   16px   1.0624em    0.1876em
    診所（改前）15px   1.1332em    0.2002em    ← 都大 6.7%

改成「名字字級的倍數」：PIN_EM = 17/16、GAP_EM = 3/16。
⚠ 兩個比值**定義在停車場那三塊上**，所以那三顆一個單位都沒動
  （transform 逐字比對：scale(0.03320)、間距 3.00）。會變的只有診所那一顆：
  17 → 15.94、間距 3 → 2.81。
⚠ 盒子用圖釘自己的 viewBox 384×512，**不要**改成 getBBox() 量出來的
  ink box（實測 384×510.675，水滴的尖端是圓的）—— 那會讓停車場那三顆
  一起長 0.26%。

三、第二次回報：「圖釘和芳有點近」

第二輪把相對量對齊之後，使用者仍然說近。量出來也是真的，而且是另一件事：

**間距一直是量到 getBBox().x，那是字的排版起點，不是看得到的第一筆墨。**
第一個字自己的左側空白（left side bearing）每個字都不一樣：

    牌子          第一個字   左側空白   box 間距   看得到的空隙
    斗六永樂站      斗        0.75       3.00       3.75
    合廷            合        0.25       3.00       3.25
    壹車房          壹        0.75       3.00       3.76
    芳仁牙醫診所    芳        0.234      2.82       3.05   ← 全場最小

「芳」的字幾乎撐滿字身、左邊幾乎沒有空白，所以同樣的 box 間距，
看起來就比停車場那三塊近了 0.7。

定案：診所那塊的間距改成**對字面量**，JS 用 canvas 現量第一個字的左側空白
再補回去（data-ink-gap="3.75"）。3.75 ＝ 斗六永樂站與壹車房的實測值，
是三塊裡的多數。改完是 3.75／3.25／3.76／3.75。

⚠ **停車場那三塊一個值都沒動。** 它們自己就不一致（合廷 3.25，因為「合」的
  左側空白大），但那是定案過的東西 —— 為了「一致」去動它，等於改掉別人簽過的版。
⚠ 這個 3.75 是**絕對單位不是 em**。和上一節「圖釘大小用 em」剛好相反，
  理由是：四塊牌子在同一張圖、同一個縮放上並排，眼睛比的是實際的空白寬度。
⚠ 量左側空白的方法和量字面下緣同一套（CLAUDE.md 第九節第 9 條）：
  canvas 的 actualBoundingBoxLeft，**在 400px 上量再等比例縮回去**
  （Blink 在小字級回來的值顆粒很粗）。量的是第一個字不是整串。

四、定案

樣式    實心（＝停車場那三塊同一顆水滴，也就是頁尾那顆）
大小    data-pin-k="0.92"     釘高 15.94 → 14.63（0.975em）
間距    data-ink-gap="3.75"   對字面量，box 間距因此是 3.51

兩個值都寫在 .clab 這個元素身上，不是寫在 JS 的常數裡 ——
牌子自己的例外就放在牌子自己的標籤上，日後 grep 得到。

五、落選：線條版的圖釘

使用者問「還是另外做一個是線條，變成是用白線條取代成現在白實心的樣子」，
所以提案頁做了一版 Lucide 的 map-pin（站上 HERO 窄帶那組線條圖示就是同一家），
描邊 2、圓角端點，顏色一樣是紙卡色。使用者選了實心。

⚠ 線條版的**盒子不能用 384×512**：那是實心水滴的 viewBox，Lucide 是 24×24，
  而且畫出來的東西只占 (4,2)~(20,22)。要把「看得到的輪廓」對齊實心版的高度，
  盒子得現量：getBBox() ＋ 描邊寬（getBBox 不含描邊）。
⚠⚠ **不要用 getBoundingClientRect() 量 <g> 的大小** —— Chrome 回傳的是
  幾何外框、不含描邊，線條版會少算一整個描邊寬（實測 14.49 vs 真正的 15.94）。
  第一版的現場量測就是這樣量的，數字整個是錯的。

六、提案頁踩到的兩件

⚠⚠ **把 data-views-self 換成 data-count 的時候，要比對整個標籤。**
  index.html 在那個 <p> 上面有一段註解，裡面就先出現了一次
  data-views-self="home"。只比對屬性字串的話，String.replace 會改到**註解**，
  真正的屬性原封不動留在頁面上 —— 症狀是「看起來都對，但提案頁還是會把首頁
  的計數 +1」。這和 CLAUDE.md 第八節那條「切換條要用 lastIndexOf 找 </body>」
  是同一種坑：這一站的註解很長，要換的字串常常在註解裡先出現一次。
  改成比對 <p class="band-views" data-views-self="home"> 整串，
  換完再 assert 一次頁面上沒有殘留。

⚠ **本機預覽伺服器是別的 session 開的，它一關網址就死。** 使用者回報
  「無法開啟」，查出來不是頁面的問題 —— 8791 沒有人在聽。
