起因

使用者 2026-08-22：「一般牙科的著陸頁並沒有我們剛剛做好的那張圖片，但那個圖片放進來 會壓縮到版面，我不要那樣。我想到把圖片的某個部分做成頁面的底，但只要保留線條， 而且是做成一般牙科的主題綠。你們幫我找看看圖片的區塊哪邊適合（我想到是畫面中間的 女醫事人員和老先生對話的部分，或是右邊兩個醫事人員輕鬆自然和其他人打招呼的樣子， 應該節錄他們的半身就好）和放在著陸頁上的位置。」

⚠⚠ 走錯的第一條路：從既有插畫「抽線稿」

做了兩版都不對，而且成因是方法本身，不是參數沒調好：

抽線稿使用者的參考圖
筆畫怎麼來的從有陰影、有材質的插畫上「撿邊」一開始就是畫出來的均勻筆畫
粗細跟著原圖明暗走，同一條線忽粗忽細從頭到尾同一個寬度
雜訊牆面材質、衣服皺褶、頭髮都變成線只有輪廓
曲線二值化後帶鋸齒（原檔是 JPEG）平滑

第二版已經做到「平塗 ＋ 放大四倍 ＋ 侵蝕收細」，線的濃度確實統一了， 但粗細的不規則與材質雜訊留在原檔裡，不是後製拿得掉的。使用者： 「我覺得這不是我要的，跟我找的範例還是差很多。你們做成圖片提示詞好了。」

⚠ 通則：要一個「畫出來的」風格，就得畫，不能從別的畫上撿。 （ILLUSTRATION.md 第十之一節那條的反面：形狀要用參考圖，但風格不能靠後製湊。）

抽線那條路的程式碼留在 tools/topic-lineart.mjs 的 --region 分支， 是為了記住那條路長什麼樣，不是還在用。

改用生成：第一版風格全過、內容四件全錯

使用者：「風格對了，不過細節跑掉了。右邊女生的髮型和表情、左邊男生的姿勢， 現在變成彼此互看，而且男生這個對前方招手很像選舉看板，跟原圖輕鬆親切的 和別人打招呼不一樣。」

風格這一側每一格都過（node drafts/lineart-measure.mjs）： 線佔畫面 6.4%、筆畫寬中位 6.8‰、粗細一致（p90÷中位）1.43（門檻 2.5）、 實心填色 0 塊（最高填滿率 .13）、四角乾淨。

⚠⚠ 四件錯的裡面有三件是提示詞自己寫出來的，不是模型亂畫：

使用者說的原本寫的那一句為什麼會變那樣
彼此互看turned slightly towards the dentist, mid-conversation我叫她轉向他。原圖裡兩個人都看著畫面外的左邊，誰都沒有看誰
很像選舉看板one hand raised in a relaxed, everyday wave「relaxed」是形容詞，擋不住正面、對稱、五指張開的平掌。要寫幾何：手只抬到下巴高、手肘收在身側、掌心斜的、手指鬆
髮型Hair is drawn as an OUTLINE ONLY只講了畫法，沒講是什麼髮型。原圖是紮起來的低馬尾
表情（沒寫）原圖她嘴巴是張開的，正在講話

⚠ 通則：動作、髮型、視線方向這種「形狀」，用文字形容一定會漂 （ILLUSTRATION.md 第十之一節）。第二版加附 drafts/lineart-pose-ref.png （原圖那兩個人的乾淨裁切，含腿 —— 腿留著是因為「走著」這件事是靠步伐讀出來的）， 一次就中。

要附的七張分三組，說明必須分開寫：五張線稿參考只提供畫法、 姿勢參考圖只提供姿勢・視線・髮型・表情、 assets/og-topic-general.jpg 只提供長相・服裝・年齡層。 第一版就是少了中間那一張。

⚠ 使用者那五張參考圖裡的第 3、4、5 張有實心黑的頭髮，我們這張不要 —— 量出來它們的「粗細一致」是 13.6／9.3／19.3（第 1 張只有 1.2），超出來的全是那幾團填色。 我們這張要當頁面的底、還要降透明度，一團實心色塊會變成一塊礙眼的綠斑。

⚠ 生成的線稿要先裁

模型多畫了一條地面線（1024 寬上的第 912~917 列，橫跨畫面 64%），四周還留一大圈空白。 那條橫線擺到頁面上會變成一條莫名其妙的橫槓，空白則讓定位很難算。 tools/topic-lineart.mjs 因此加了 --crop x,y,w,h，裁完圖檔就等於內容本身：

node tools/topic-lineart.mjs general --art drafts/lineart-general-v2.jpg \
  --crop 97,123,832,788 --out assets/lineart-general.png

⚠ 那個「線佔超過 12%」的警告只對未裁的整張圖說話 —— 裁掉四周空白之後同樣的線會佔到 兩倍以上，那不是變糟。所以有 --crop 時不比。

⚠⚠ 這一輪最要緊的兩句

一、大小不影響對比度，位置才影響。 字壓在線上時最壞的底色 ＝ 紙色與套色按濃度混合，和圖多大完全無關； 圖變大只是讓更多字落在那個底色上。

二、卡住的是柔墨的次要文字，不是主文。閉式解（紙 #e2e5e6、套色 #3f654a）：

紙上.20.32.48掉到 4.5 的臨界
主文 --ink #2a2c2711.158.537.165.65.58
次要 --ink-soft #5c5f575.143.943.302.58.101

.tp-case／.tp-flow（那幾個現場與流程）用的正是柔墨， 它在紙上本來就只剩 0.64 的餘裕。所以「有字壓到」的那一段天花板是 .10，不是「看起來淡不淡」。

⚠⚠ 而「有沒有字壓到」完全是寬度決定的

提案頁現場量「有多少比例的字落在圖上」（把介紹區每一段文字的行框拿出來， 和浮水印的矩形取交集，除以行框總面積）：

寬度小中大特大
1440／1200／1041／8340%0%0%0%
4308%20%33%46%
39011%20%33%46%
37511%21%27%42%

那幾行文字都比介紹區窄（iPad 上一行約 420px、區塊寬 784px）， 所以右下角在平板以上是真的空白，只有手機才會壓到字。

⚠ 切換條的量測面板要直接下判斷，不要只印數字（同 tag-fade 那一輪）： 面板先算「有多少字落在圖上」，0% 就直接說「濃度只影響好不好看，不影響可讀性」， 不會死板地印一個過不了的對比度。

定案

使用者分兩次選：先「手機版這樣，其他我再來看看」（特大・右下・極淡）， 再「你們分析的很有道理，而且這樣平板、電腦上看效果很好，就這樣吧」（≥834 用濃）。

[data-topic="general"] .tp-intro { position: relative; }
[data-topic="general"] .tp-intro::before {
  content: ""; position: absolute; right: 0; bottom: 0;
  width: min(76%, 360px); aspect-ratio: 832 / 788;
  background: url("assets/lineart-general.png") center / contain no-repeat;
  opacity: .10; pointer-events: none; z-index: 0;
}
@media (min-width: 834px) { [data-topic="general"] .tp-intro::before { opacity: .48; } }
[data-topic="general"] .tp-intro > * { position: relative; z-index: 1; }

⚠ 濃度分兩段是量出來的，不要收成一個值：手機 390 壓到 46% 的字 → 只能 .10 （實測 4.51，剛好過）；≥834 壓到 0% → 濃度純粹是美感，使用者選 .48。

落選 / 沒選上的

  • 位置「右側」（介紹右邊那塊空白，≥1200 才出現）—— 電腦上很好看， 但它在平板與手機完全不存在，而「右下」在平板以上一樣不壓到字、還多涵蓋了 834~1199。
  • 位置「右下（平板以上）」（手機不放）—— 使用者要手機也有。
  • 位置「不放」。
  • 大小 小／中／大（min(40%,180px)／min(52%,240px)／min(64%,300px)）。
  • 濃度 淡 .20／中 .32（手機那一段這兩格都沒過 4.5）。

踩過的坑

⚠⚠ background-image 吃不到 opacity。 第一版把圖直接掛在 .tp-intro 身上，濃度那條尺對它完全沒作用 —— 手機上它是全濃度壓在內文底下，量出來「改變的面積 0.0%」就是那個徵兆。 改用 ::before ＋ opacity。

⚠ right 不能給負值：手機上介紹區已經貼著版心，往外凸就會多出水平捲動 （390 上 -1rem 直接讓整頁可以左右拉）。

⚠⚠ 提案頁第一版在手機上一片空白（使用者：「好像沒有欸」）—— 側邊那一格只在 ≥1200 出現，而他所有東西都用手機看。做法和訊息卡那幾張一樣： 擺真的東西，然後縮到看得到的尺寸（iframe 載同一頁、寬度鎖 1440， 再用 transform 縮到手機寬，iframe 裡帶 frame=1 那一態不畫預覽框也不畫切換條）。

⚠⚠ 那一版真正的成因是插錯位置而且不報錯：<body> 這幾個字 在 <head> 的註解裡出現四次，String.replace 會抓到註解裡的第一個， 整塊就插進樣式表中間、完全不會顯示。要從 </head> 之後才開始找。

⚠ <!-- SEO:START 後面還跟著一句「由 tools/topics.mjs 產生，請勿手動編輯」， 不能用整串比對，只找前綴。

⚠ 模板字串裡的 CSS 註解不能出現反引號（CLAUDE.md 第九節第 8 條的近親）—— 寫了就把樣板提早關掉，整支腳本語法錯誤。這一輪踩了兩次。

⚠⚠ CSS 裡的 url() 在做著陸頁快照時也要改路徑。 tools/topics.mjs 原本只換 href=／src=／srcset=， 而樣式表整段是從 index.html 照抄過來的 —— url("assets/…") 在 /topics/<spec>/ 底下會解成 /topics/<spec>/assets/… 而 404，而且瀏覽器不會報錯，只是圖不見。 ⚠ 不要改用根目錄絕對路徑 /assets/… 代替 —— 舊站 yclee86.github.io/fangren-dental/ 還活著，那邊會壞。

⚠ 量筆畫寬不能只掃橫向：一條水平的線在橫向會量成「整條線那麼長」。 每個墨像素要取「橫向連續長」與「縱向連續長」較小的那個再取中位。

⚠ 量「有沒有實心填色」不能只看面積：一整個人的輪廓也是一大塊連通區域， 但它是空心的。要看填滿自己外接矩形多少（> 0.5 才算填色）。

⚠ 量寬度用的探針要插在 .tp-intro 裡面 —— 寬度是 min(76%, 360px) 這種式子，百分比要對得上正確的父層才算得對。

驗收

九個寬度（1440／1280／1200／1041／834／430／390／375／320）介紹區高度與加圖之前 逐格相同（546.2／546.2／546.2／546.2／546.2／473.6／473.6／501.1／693.7）， 沒有任何水平捲動。使用者那句「放進來會壓縮到版面，我不要那樣」是靠 absolute 的偽元素達成的，markup 一個字都沒動。 其餘六科與首頁逐頁確認沒有畫出這個偽元素。

其餘六科

牙周／兒牙／顯微根管／植牙／口外／矯正還沒有自己的線稿。 畫好之後：跑一次 tools/topic-lineart.mjs <spec> --art <檔> --crop …， 再把 [data-topic="<spec>"] 加進上面那三條選擇器的清單裡。 不要改成 [data-topic] 一網打盡 —— 沒有圖的科目會畫出一個空的偽元素。 提示詞的骨架在 drafts/topic-lineart-prompt.md，換人物與場景就好， 風格那幾段一個字都不用改。
