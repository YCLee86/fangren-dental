起因

使用者：「我想要文章點開後出現該科的醫師資訊（不然看文章還要回去查有誰在做這個相關治療）」
名單：回頭讀 index.html 的 #doctors，規則和首頁點科別、七科著陸頁同一條 ——
　　　專科是這一科，或專長裡有一顆是這一科。一般牙科 4 位、假牙 3 位、牙周／矯正／兒牙各 2 位、
　　　口外與根管各 1 位。

五輪

一　內容 × 位置兩條尺
　　內容　Ⓐ 頭像＋名字＋專科　Ⓑ 再加這一科的專長 ← 定案　Ⓒ 完整醫師卡（同首頁）
　　　　　　Ⓒ 落選的量測：手機 375 上一般牙科那篇多捲 1486px（Ⓑ 是 423px）
　　位置　① 內文結尾（上下篇按鈕之前）← 定案　② 延伸閱讀上方

二　使用者：「點文章內的醫師卡跳回首頁的醫師介紹圖卡」
　　→ 首頁九張醫師卡加 id="doc-<代號>"，整列蓋一層透明連結，跳過去那一張外框亮一下

三　使用者：「文章要看到最下面才看到的醫師，可以怎麼處理」
　　四個做法：頂端那一行加入口／捲動時底部浮一條／電腦版右側固定欄／插在內文中間
　　→ 前兩個做成提案（入口：無／1／2／1＋2）

四　使用者：「入口 1＋2 但不要頭像」「那個底部浮條太大了，我們在首頁做過點下去移到最頂的按鈕，
　　可以把那個概念用在這裡」
　　→ 底部浮條換成右下角一顆小方塊，外觀逐項照首頁「回到最上面」的 .btt
　　　 記號三案：Ⓐ 人像圖示　Ⓑ「醫師」　Ⓒ「醫師 ﹀」← 定案（64×44，比 .btt 寬）

五　使用者（手機截圖）：「標題上面的醫師要斷行到下面，白天夜間切換桿在原來的位置」
　　→「N 位醫師 ›」排在頂端那一行的最後、自己佔一列（order ＋ flex-basis 100%）
　　　 實測 320／375／390／430／744／1440 × 瀏覽數 63／1,234：開關位置與沒有它時逐項相同

定案（＝ 現在站上的）

那一塊　內文結尾、上下篇按鈕之前。標題「這一科的醫師」＋ 右上「○○・N 位 ›」（連到著陸頁）
　　　　一位一列：頭像 52px ＋ 名字 ＋ 專科藥丸 ＋ 這一科的專長（淡色填滿）＋ ›
　　　　整列點下去 → /#doc-<代號>（首頁那一張外框亮 2.4 秒）
　　　　專科藥丸：本科實心、不是本科退成白底（同首頁點科別的規則）
入口一　頂端那一行底下「N 位醫師 ›」，純文字、不要頭像
入口二　右下角「醫師 ﹀」，捲過半個螢幕出現、那一塊進到畫面就收起來
兩個入口點下去都平滑捲到那一塊（減少動態效果開著就直接跳）

⚠ 上線時要知道的

・那兩塊在 <main> 裡，由 tools/build.mjs 寫（DOCS／DOCPEEK 兩個區塊），
　normalize() 把它們**連同插入時補的空白整段拿掉**再算雜湊 —— 所以二十篇的「最後更新」一天都沒跳
　（上線前後比對 build-manifest.json：二十篇的 hash 與 updated 逐篇相同）。
・專科藥丸與專長標記的樣式原本只在 index.html，這一次抄一份進 assets/style.css。
　首頁那邊的上下內距由 skFit() 現量，文章頁吃的是同一組後備值（提案四輪看到的就是這一組）。
・點擊紀錄多四種代碼：doc-peek、doc-btn、doc:<代號>、doc-more:<科別>
　（src/click.js、assets/click-log.js、/admin/search/ 三處一起加；click-test 104 項過）。
・醫師卡的 id 寫在屬性的最後面：topics.mjs 要 class 後面緊接 data-spec、schema.mjs 要 class 後面緊接引號。

・⚠⚠ 同一輪發現、**沒有修**的既有問題：七科著陸頁的專科藥丸全部是白底。
　topics.mjs 判斷「這位醫師的專科是不是這一科」寫的是 class 後面緊接 data-spec，
　2026-09-19 有照片的卡多了 data-face 之後就比對不到了（只有沒照片的廖立揚醫師還是實心）。
　名單本身沒受影響（每一位都有一顆這一科的專長）。要不要修，帶回去問使用者。
