2　浮水印挑哪一顆、每一顆要填什麼、畫多大、擺在哪

2-1　挑哪一顆

  • 形狀 ＝ 順序[(月 ＋ 日) % 9]，順序固定是 r1c1 r1c2 r1c3 r2c1 r2c2 r2c3 r3c1 r3c2 r3c3（＝九宮格由左到右、由上到下）。
  • 月與日取那一筆約診的看診日期 —— 不是今天，也不是它排在清單裡第幾張。
  • 顏色綁在形狀上（下面那張表），不必另外算一條規則。
  • 兩則吃同一條規則：同一筆約診在「預約成功通知」與「約診紀錄查詢」上會是同一顆、同一個顏色。
  • 所以同一筆查幾次都一樣。不要用清單位置輪流，也不要隨機 —— 前者取消一筆會讓後面每一張都換人，後者同一筆每次看都不一樣。

2-2　每一顆要填什麼

  • url　https://fangren.net/assets/line/wm-<形狀>-12.png。12 是濃度：淡是烘在 PNG 的 alpha 裡的，因為 Flex 的 image 沒有 opacity。
  • size　照下表那一則那一欄。Flex 的 image size 給的是寬度。
  • aspectRatio　照下表。每一顆不一樣，不要寫死一個 —— 寫錯不報錯也不變形，只會靜靜地縮小、四周留白。
  • aspectMode　"fit"（兩則相同）。
  • position　"absolute"，貼卡片的右下角、疊在文字上面。一個 box 的第一個子元件不可以是 absolute，所以先放正常的內容 box，浮水印排在它後面。

2-3　位置與大小

定案

  1. 位置：往右下溢出 18／10px，卡片把跑出去的那一塊切掉 —— 不是貼齊右下角、整顆收在卡內。

  2. 寬度：兩則各一欄，那不是筆誤（2026-09-14 定案）。九顆的寬度不一樣是刻意的（按墨的面積算的，這樣看起來才一樣重），而兩則的卡片寬差 106px，同一個 px 佔掉的比例差很多 —— 所以那份 Flex JSON 的浮水印 size 拆成兩個欄位：單張吃 watermark_size_single、輪播吃 watermark_size_carousel。每一顆在兩則上各要填多少，見下面那張表（收窄過的那幾格括號裡標著原寬）。

  3. 顏色：淡墨素色，柔墨 #5c5f57、濃度 12%。

  4. 卡片底色：純白 #FFFFFF（2026-09-14 定案）。這一項你們現在跑的就是純白，不必換 —— 逐像素量過你們 09-10 送來的三張截圖，卡片內部是 #FFFFFF；先前我們這一份寫的是 #F4F4F5（診所網站的卡片色），同一天已經改成純白對齊你們。其餘五則沒有動。

  5. 那份 Flex JSON 裡 offsetEnd／offsetBottom 仍然寫著 0px，因為 Flex 的 offset 不吃負值、表達不出溢出。你們 09-10 那一版已經做出溢出了（量到 8~10／6~7px）—— 請照你們的做法，把溢出量統一成 18／10px。

你們現在送的

廠商送來的兩張卡上，浮水印確實是這九顆裡的兩顆，形狀與各自的顏色都對得上（圓形＋紫 ＝ 口腔外科那一顆；寬形＋青綠 ＝ 牙周治療那一顆）。

大小與位置

大小與位置和我們的規格不一樣。量法是拿形狀中間那個牙洞當尺（牙洞占圖寬的比例是固定的），所以圖被切掉也量得出它本來多大。

要換的規則

(約診月份 + 約診日) % 9，照上面那張表由上到下的順序取第幾顆。同一筆約診不管查幾次都是同一顆；預約成功通知與查詢清單裡的那一張，也要是同一顆、同一色。（送來的那一批裡，同一筆約診 2020/09/11 09:00 在 14:20 是圓形、14:23 是寬形。）

請照這樣填

問法因此不是「是不是限制」，是你們的 size 寫成 px、關鍵字、還是百分比，填的是哪一個值。三種寫法各有一個會讓它變小的機制，三種都改得動：關鍵字是一把粗的階梯、填不進 104 或 150；百分比的基準是它的父層 box，父層若是有內距的內容框就會小一截；px 就只是填了別的數字。這三條我們只有文件上的理解、沒有實機驗過，所以先當成問題請你們確認；要填的值都在上面那張表裡。

2-4　九顆的形狀與色碼

浮水印的顏色改成淡墨素色：柔墨 #5c5f57，壓在卡片上的濃度維持 12%（檔名 wm-<形狀>-ink12.png）。形狀、寬度、位置一個數字都沒動，換掉的只有顏色。下面九顆上面那一排仍然印原色，那一份色是第 3-2 節那四個值在用的，不是浮水印的顏色。那九顆底下寫的「原寬」是按墨的面積算出來的基準，不是要填的值 —— 實際要填的是上面那張表那兩欄。
每一格上面是原色（看得出形狀與是哪一科），虛線底下是它壓在卡片上真正的樣子 （淡墨 #5c5f57，濃度 12%）。 兩張是同一份幾何、同一個相對寬度 —— 九顆的寬度不一樣是刻意的（按墨的面積正規化，看起來才一樣重）。

3　卡片兩則各用哪一階、內距、底色、哪一格不要限制行數

3-1　卡片本身

  • 單張（預約成功通知）　bubble size: "mega"（LINE 上約 268px，這一頁的模擬圖就畫這個寬度）。
  • 輪播（約診紀錄查詢）　bubble size: "micro"（LINE 上約 162px）。你們現在跑的是 deca（約 207px），這一項是要請你們換的；換的時候同一條輪播必須整組一起換，不能只縮其中一張。
  • paddingAll　14px（兩則相同）。
  • backgroundColor　#FFFFFF（兩則相同）。這一項你們現在跑的就是純白，不必換。
  • 日期那一格一定要 wrap: true、不要 maxLines。現在那個 maxLines: 1 正是日期被截成「…15:45 星...」的成因。

3-2　約診狀態那一列

2026-09-12 一格一格挑完了，整理成一段可以直接照做的規格。它只為「那個欄位移不掉」那條路存在 —— 第一層要問的仍然是：病人自己按過取消的那一筆，能不能就不要列在他的查詢清單裡（樂衍後台照舊保留）。

四張卡各掛一個值 —— 一張卡上看不出四種的相對份量。卡片畫成輪播上真正的寬度（207px），兩行內容照你們 09-10 那一版，日期是調過排法的那一種（星期幾接在日期後面、時間自己一行），所以星期幾一定跟著它的日期，不會被折到下一行去。浮水印是定案的淡墨、往右下溢出。這四張的浮水印是這一筆日期算出來的那一顆（r1c3）。

欄位名

約診狀態（廠商現在印的是「預約狀態」）。改的只是卡片上印出來的那個標籤，資料庫欄位叫什麼名字不必動。

四個值

已排定／已確認／未回覆／已取消。

色票

齒顎矯正 #4478b5／一般牙科 #3f654a／兒童牙科 #c28229／顯微根管 #ae4f4d（＝第 2 節那九顆的同一份色）。

畫法

底套色、白字、加粗的藥丸，圓角 8.5px（站上那一族）。Flex 寫成 horizontal box、藥丸那一格 flex: 0、後面補一個 filler，藥丸才會只包住那幾個字而不是撐滿整列。

對齊

基線對齊（三種比過之後挑的）。

標籤

「約診狀態」那四個字維持不加粗、不套色。

浮水印

那張卡的浮水印換成淡墨色（柔墨 #5c5f57，wm-<形狀>-ink12.png）。形狀、寬度、濃度一個數字都沒動，換掉的只有顏色。

先問的是哪一題

這一整節只為「那個欄位移不掉」那條路存在。第一層要問的仍然是：病人自己按過取消的那一筆，能不能就不要列在他的查詢清單裡 —— 做得到的話那一列根本不會出現，底下這些都不必做。

還要一支測試訊息

藥丸裡那個字怎麼坐在盒子裡是 LINE 決定的（text 沒有行高可以設）。我們寫得出 paddingTop／paddingBottom，但對不對得上要實際送一則出來看。

4　照這個規格畫出來的樣子卡片畫成兩則真正的寬度

4-1　預約成功通知（單張 mega）

同一張卡畫2次

同一張卡（268×121）畫兩次：我們要的、廠商 09-10 送來的。卡上四行就是這一則真正的內容，形狀與顏色完全一樣，差的只有浮水印的大小與位置。卡片的高度是那四行自己撐出來的：日期收成一行之後（見第 2 節那一條），比現在那一張矮 28px，文字底下那一塊空白就跟著不見了。

寬形（牙周治療青綠）・預約成功通知

約診查詢那條輪播（卡寬約 207）上的寬形也量過：畫出來 80px ＝ 卡寬的 38.6%，規格是 150px ＝ 72.5%。三張合起來，廠商畫的是我們規格的 53~65%。

九顆各自畫在卡片上該有的樣子

九顆各自畫在那張 268×121 的卡上、照規格的寬度往右下溢出 18／10px（＝定案那一種），顏色就是定案的淡墨。卡上那四行就是這一則真正的內容（從我們給你們的那份 Flex JSON 讀出來的，不是另外打一份），所以看得出浮水印是墊在字底下的一層，不是排完字之後另外塞進去、把對話框往下撐開的一塊。九顆都在這裡，不是只有你們已經用過的那兩顆。

4-2　約診紀錄查詢（輪播 micro）

底下輪播那幾張模擬圖畫的是你們現在跑的 207px，不是我們要的 162px —— 這樣它和第 3-2 節那四張、和你們送來的截圖才比得起來。換成 micro 之後卡片會再窄 45px，那時日期那一行放不下，要請你們在輪播那一格的值裡帶一個換行（2026/09/11 換行 星期五 11:50），單張那一則維持一行。

同一張卡畫2次

約診紀錄查詢那條輪播上的同一顆也量過。兩張差的是大小：你們畫成卡寬的三成八，規格是七成二。位置那一項在輪播這張上沒有單獨量過，所以兩張都照定案的溢出量畫。

九顆各自畫在卡片上該有的樣子

同樣九顆，這一次畫在輪播那張卡上、照上面那張表輪播那一欄的寬度。卡上那兩行一樣是那份 Flex JSON 裡真正的內容。輪播的卡比單張窄，所以同一顆佔掉的比例大得多 —— 那正是寬度要分成兩欄的理由。這一則多一列「約診狀態」，見第 3-2 節。
